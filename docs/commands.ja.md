# コマンド

`floe` のすべてのコマンドの参照です。データファイルの書き方は [pages.ja.md](pages.ja.md) にあります。

## インストール

インストールのコマンドは [README](README.ja.md#インストール) にあります。`FLOE_VERSION` でリリースを固定し、`FLOE_INSTALL_DIR` でインストール先（既定は `~/.local/bin`。Windows は [Windows](#windows)）を変えられます。バイナリはリリースの `SHA256SUMS` で検証します。

サーバーや途中のプロキシが応答しなくなったときは、待つのをやめます。何も届かない状態が `FLOE_INSTALL_TIMEOUT` 秒（既定は `120`。`1` から `99999` までの整数）続くと、取得しようとしていた URL を表示して終了します。この上限は 1 回のリクエストごとに適用されます。リクエストはリダイレクトを含めて 5 回ほどあるので、すべてが上限の直前まで応答しない場合は、終了まで 10 分ほどかかります。ダウンロード全体の時間に上限はありません。遅くても届き続けているダウンロードは打ち切りません。`install.sh` は、サーバーが毎秒 1 バイト以上を送り続けている間は待ち続けます。

## 早見表

フラグは、下の各コマンドの節にあります。

| `floe publish <data.yaml>` | データファイルから描いたページを保存し、またはファイルかフォルダをその場で登録して、URL を出す |
| `floe check <data.yaml>...` | データファイルを、ページを描くとおりに確かめる。何も書かない |
| `floe render <data.yaml>...` | 各データファイルのページを、リポジトリに置く HTML のファイルに書く |
| `floe rebuild` | 保存したページを、今のテンプレート・部品・テーマで描き直す |
| `floe template list` | テンプレートを並べる |
| `floe template show <名前> [ファイル]` | テンプレートのテーマと、読むファイルの並びを出す。ファイル名を足すと、そのファイルを書いたとおりに |

| `floe template guide` | 自分のテンプレートの作り方を出す |
| `floe part list` | floe のテンプレートの節に書ける部品を並べる。全部の部品・見た目・共有の schema を並べることもできる |
| `floe part show <名前> [ファイル]` | 部品・見た目・共有の schema（`html` なら `any.json`）と、読むファイルの並びを出す。ファイル名を足すと、そのファイルを書いたとおりに |
| `floe part new <名前>` | 埋めて使う最小の自分の部品を作る |
| `floe part check` | 自分の部品・見た目・共有の schema・テーマを確かめる |

| `floe theme list` | テーマを並べる |

| `floe theme new <名前>` | 埋めて使う最小の自分のテーマを作る |
| `floe theme check` | 自分の部品・見た目・共有の schema・テーマを、`floe part check` と同じに確かめる |
| `floe theme guide` | 自分のテーマの作り方を出す |
| `floe theme default` | 管理ページの設定で選んだ既定のテーマを出す |
| `floe list` | ページを新しい順に並べる |
| `floe info <slug>` | ページのプロジェクト・タスク・データファイルなど、floe が持つものを出す |
| `floe rm <slug>...` | ページを消す |
| `floe archive <slug>...` | ページを消さずに一覧から外す。あとで戻せる |
| `floe tag <slug>...` | ページにタグを付ける・外す |
| `floe task` | プロジェクトの着手前・作業中のタスクと、ページのタスク・カテゴリ・ピンを言う。ページをタスクに載せる、ピン止めする、タスクを変える |

## `floe guide`

エージェント向けの手引き [guide.md](agents/guide.md) を出します。ページの書き方・検査・出し方、テンプレートと部品の選び方、floe が書いたとおりに読む YAML、誤りの読み方です。この docs の要約で、エージェントがページを書く前に読みます。Tasks の節は `floe task guide` を指し、その中の Ask after publishing（新しいページを publish するたびに、どのタスクのどのカテゴリに置くかを、質問ダイアログでユーザーに聞く決まり）は、管理ページの設定でタスクモードが入のときだけ出します。設定は、ほかのコマンドが送る保存先（`FLOE_DIR`）から、サーバーを起こさずに読みます。保存先を決められないとき（`HOME`（Windows では `USERPROFILE`）が絶対パスでなく、`FLOE_DIR` も無い）は、その節を除いて出します。`settings.json` を読めないとき、`FLOE_DIR` が使えないときは、`floe theme default` と同じく断ります。引数は取りません。

## `floe skill install <agent>`

floe のスキル `floe/SKILL.md` を、名指したエージェントが全部のプロジェクトのスキルを読む所に書きます。エージェントと置き場所は `floe skill install --help` が並べます。スキルはエージェントに `floe guide` を走らせるよう言うだけなので、floe を上げても古くなりません。書いたパスを、リンクをたどった後の形で `made <パス>` と出します。この floe の `SKILL.md` がすでにあればそのままにして、`<パス> is this floe's skill already` と言います。別のものは残して断り（終了コード 1。`pass --force` と言います）、`--force` のときだけ上書きして `replaced <パス> with this floe's skill` と言います。リンク `floe` は `floe` という名前のディレクトリへ、リンク `SKILL.md` は `SKILL.md` という名前のファイルへだけたどります（`floe render` がページのリンクを `.html` のファイルへだけたどるのと同じ）。`CLAUDE_CONFIG_DIR` を設定していると、`claude` はその下に書きます。そこのディレクトリが使えなければ設定の誤りとして、その下のファイルの誤りはそのパスで言います。

## `floe publish <data.yaml>` / `floe publish --link <file|folder>`

データファイルのページを、そこに書いたテンプレートで描き、描いたとおりに保存して、URL（`http://127.0.0.1:7325/a/<slug>/`）を標準出力に、描いたページの警告を `floe check` と同じに標準エラー出力に出します。ページが新しい、またはプロジェクトが変わったときは、それを言う 1 行（`page in project floe`、無ければ `page in no project`）も標準エラー出力に出します。サーバーが動いていなければ、先に裏で起こします。新しい slug はブラウザでも開きます（`$BROWSER`、無ければ macOS では `open`、Windows では既定のブラウザ、ほかは `wslview`・`xdg-open`）。もう一度 publish したものは開きません。開いたタブが自分で読み直すからです。ページは、新しい版の Chrome・Safari（26 以降）・Firefox（147 以降）で見るのを勧めます。

ページはデータファイル（`.yaml`・`.yml`）から描きます。書き方は [pages.ja.md](pages.ja.md) にあります。データファイルは、見せる画像とともに（データファイルが名指すパスで）`FLOE_DIR` の下の `<slug>/source-<id>/data.yaml` に写します。元を失ったら、そこから取り戻せます。publish のたびに新しい写しを書いてから前のものを消すので、失敗した publish はページを前のままに残します。相対パスは作業ディレクトリから読みます。

保存したページは描いたときのままです。テンプレート・部品・テーマを変えても、`floe rebuild` で描き直すまで変わりません。テーマを書いていないページは、初めて保存したときに管理ページの設定で選ばれていた既定のテーマを持ち続けます。既定を変更しても、変わるのはその後に保存するページだけです。管理ページでページの「…」の「テーマ」から選んだテーマは、そのページをすぐ描き直し、どれよりも強く、publish し直しても続きます。HTML のファイルなど、ほかのファイルは保存しません。そのまま見せるには `--link` で登録します。

サーバーはページを別のプロセスで描きます。1 つのページに使えるのは、メモリ 512 MiB と 30 秒までで、80 MiB を超えるページは `floe check` と同じに断ります。どれかを超えると、そのページをデータファイルの所で断り（`page.yaml: drawing it needed more than 512 MiB of memory, …`、`page.yaml: drawing it took more than 30 seconds, …`、`page.yaml: the page drawn is 96 MiB, over the 80 MiB a page may be, …`）、サーバーは動き続けます。リンクしたデータファイルのページを開くとき、ページに選んだテーマで描くとき、`floe rebuild` が描き直すときも同じです。別のプロセスで描くので、publish とリンクしたデータファイルのページを開くのは約 0.1 秒遅くなります。

### フラグ

| フラグ | 説明 |
|---|---|
| `--link` | ファイルかフォルダをその場で登録する。HTML のファイルはそのまま見せ、データファイルはページを開くたびに描き、フォルダはその下の HTML を並べる（[links.ja.md](links.ja.md)）。 |
| `--slug <名前>` | URL の名前。英小文字・数字・ハイフンで 1〜64 字、英小文字か数字で始めて終える。既定は、そのファイルのページの URL 名、無ければファイルの名前。リンクした `index.html` はそのディレクトリの名前。 |
| `--title <文>` | 一覧の題。既定はデータファイルの `title:`、リンクしたファイルの `<title>`、無ければ最初の `<h1>`、無ければ slug。 |
| `--description <文>` | 一覧に出す説明。 |
| `--theme <名前>` | ページを描くテーマ（パレットと部品の形）。データファイルの `theme:` より強い。管理ページでページに選んだテーマは、これより強い。既定は `theme:`、無ければ初めて保存したときの既定のテーマ、無ければ `default`。HTML のファイルやフォルダの `--link` とは使えない（そのまま見せるため）。 |
| `--force` | ほかのファイルのページ、ほかのファイルへのリンクを置き換える。前のものは、ページの前の版も含めて何も残さない。 |
| `--move-project` | ページがすでに別のプロジェクトに入っていても、`floe publish` を走らせたディレクトリのプロジェクトに入れる。付けなければ、ページは前のプロジェクトを保つ。`--link` とは使えず（互いに排他のフラグ）、そのディレクトリにプロジェクトが無いときも断る（ページが扱うリポジトリで走らせるよう、誤りが言う）。名前では指定しない。 |

### プロジェクトと上書き

新しいページは、初めて publish したプロジェクトに入ります。プロジェクトの名前は、`floe publish` を走らせた git リポジトリの `origin` の URL のリポジトリ名、無ければリポジトリのディレクトリ名です（worktree は元のチェックアウトと同じ）。リポジトリの外では、走らせたディレクトリの名前です。データファイルの置き場所は関係ありません。`floe publish` は、ページが新しいとき、またはプロジェクトが変わったとき（`--force` でほかのファイルのページを置き換えたとき、プロジェクトを空にしたページを publish し直したとき）に、ページが入ったプロジェクトを、URL の後に標準エラー出力で言います（`page in project floe`、無ければ `page in no project`）。プロジェクトが変わらない上書きは、何も言いません。`--link` のプロジェクトは、走らせたディレクトリでなく、リンク先のファイルのディレクトリ（フォルダはそのフォルダ）のもので、ページと同じに言います。

- ページは、そのデータファイルのものです。ファイルは、そのファイルのリポジトリと、リポジトリの根から見た道で決まり、リポジトリの外なら実体のパスで決まります。どのディレクトリから publish しても同じです。`docs/plan.yaml` は、リポジトリの根から出しても、`docs` から出しても、別の worktree から出しても、リポジトリの外から出しても同じファイルで、出し直してもページのプロジェクトは変わりません（`--move-project` を付けたときを除く）。リポジトリは名前で見分けます。同じ `origin` の 2 つの clone は 1 つのページを使い、名前が同じ 2 つのリポジトリもそうなります。
- 同じファイルからの同じ slug は、ページを上書きします。標準エラー出力がそう言います（`updated "plan" (last updated …, title "…")`）。題が変わっていれば、何から何に変わったかを警告で出します。終了コードは 0 のままです。
- ほかのファイルのページの slug は、`--force` が無ければ断ります。`--force` はページを一から作り直し、前のものは何も残しません。`--force` はページの履歴（版、固定した題、タグ、お気に入り）を捨てます。データファイルを動かしたり名前を変えたりして、同じ URL を使い続けるときは、`--force` で publish してください。`--slug` が無いとき、`--force` が置き換えるのは、そのファイルのページが無いときの、ファイルの名前のページだけです。
- 管理ページで URL 名を変えたページ（`o` を `d` に）は、元のファイルのままです。そのファイルを `--slug` なしで publish し直すと、`d` に書きます。ほかのファイルから `d` に publish すると、`--force` が無ければ断ります。1 つのファイルのページが 2 つあるとき（別の `--slug` で publish するとできます）は、ファイルの名前のページ、無ければ URL 名の順で最初のページに書きます。要らない方は `floe rm` で消してください。
- ページとリンクは、`--force` でも互いの slug を取れません。先に `floe rm` してください。
- もう一度の publish は、ページのプロジェクト（`--move-project` を付けたときは、floe を走らせたディレクトリのプロジェクトに入れます。新しいページの名前の決め方と同じで、間違ったプロジェクトに入ったページを直すためです。`--link` とは使えず、そのディレクトリにプロジェクトが無いときも使えません。ページが扱うリポジトリで走らせます。タスクはプロジェクトの中のものなので、ページはタスクから外れ、publish が URL の後にそう言います（`page in project app, off task #9`）。付け直すなら `floe task --slug <slug> --task <ID>`）、管理ページで決めたもの（題・お気に入り・タグ）、説明、作った日時を保ちます。`--title` と `--description` はそれより強いです。管理ページで空にしたプロジェクトは、publish したプロジェクトに戻ります。アーカイブしたページは一覧に戻ります。
- 同じ中身のもう一度の publish は、テーマを変えていてもページを描き直しますが、更新時刻と一覧の順は動きません。中身が違えば上がります。ファイルのリンクの一覧の時刻は、ファイルの更新時刻と登録した時刻の遅い方で、登録し直すと上がります。フォルダの行には時刻を出さず、一覧の並びは登録した時刻（登録し直した時刻を含む）です。

### リンクしたファイル

`--link` は、ページを保存せず、ファイルかフォルダをその場で登録します。それぞれの見せ方は [links.ja.md](links.ja.md) にあります。

- 登録できるのは、ふつうの `.html`・`.htm` のファイル、データファイル（`.yaml`・`.yml`）、フォルダだけです。データファイルは、`floe check` と同じに確かめ、誤りがあれば断ります。
- 断るもの：ホームの直下の隠しディレクトリ（設定や鍵がある所）そのものと、その中のファイルとフォルダ。`/` やホームの直下のファイルと、`/` とホームそのもののフォルダ（ディレクトリ全体を配信することになるため）。HTML のファイルやフォルダへの `--theme`。
- `--slug` の無いリンクは、同じファイルの slug（名前のものを先に）を使い、無ければ `name`・`name-2`・`name-3` … の空いた最初のものを取ります。リポジトリの中のフォルダは、プロジェクトの名前とリポジトリの中の場所（`api-docs-docs`）で名付けるので、同じ名前のフォルダが、いくつものリポジトリにあっても URL で分かれます。リポジトリの外のフォルダは、フォルダの名前（`handbook`）です。ほかのファイルへの同じ slug は、`--force` が無ければ断ります。同じファイルをどのディレクトリからリンクし直しても、ページと同じく、リンクのプロジェクトは変わりません。

## `floe check <data.yaml>...`

各データファイルを、ページを描くとおりに確かめます。YAML、テンプレートとテーマ、テンプレートの schema、checks と計算した値、描いたページです。テーマを書いていないページは、保存先の設定の既定のテーマでなく `default` で描きます。相対パスは作業ディレクトリから読みます。

- 全部のファイルの誤りを、`file:line:column: message`（ファイル全体の誤りは `file: message`）で、渡した順に出します（終了コード 1）。確かめの 1 つの段の誤りは全部まとめて出し、前の段に誤りがあれば後の段は走りません。読み方は [pages.ja.md](pages.ja.md#誤りの読み方) にあります。
- 描けたページの警告（より良い書き方の勧め）を、誤りの後に `file:line:column: warning: message` で出します。警告は終了コードを変えません。[pages.ja.md](pages.ja.md#警告) にあります。
- どのファイルも正しく、警告も無ければ何も出しません（終了コード 0）。
- 何も書かず、サーバーも起こさないので、リポジトリの CI でデータファイルにかけられます。
- 描くのに使えるメモリは 512 MiB までです。超えると、floe は描くのを止め、描いていたファイルにそれを言います（`file: drawing it needed more than 512 MiB of memory, …`、終了コード 1）。その前のファイルの誤りは言いません。式や `page.html` で長い文字を項目ごとに繰り返すページは、それだけ要ります。描いたページの HTML が 80 MiB を超えるときも、データファイルの所で断ります（`file: the page drawn is 96 MiB, over the 80 MiB a page may be, …`）。
- データファイル（`.yaml`・`.yml`）でないファイルは断ります。
- 2 回名指したデータファイル（2 つの glob、シンボリックリンクのディレクトリ越し）は 1 回だけ確かめ、最初に渡したパスで言います。大文字と小文字だけが違う名前は、大文字と小文字を区別しないファイルシステムでも、別の名前として読みます。

## `floe render <data.yaml>...`

各データファイルを描き、ページを `<名前>.html` としてデータファイルの隣に書きます。リポジトリが、エージェントが読み書きするデータファイルと、人が読むページを両方持てます。ページは管理ページがダウンロードするものと同じで、floe 無しで開け、見せるもの（画像、図のスタイルと拡大）を全部持ち、スクリプトが中身を外へ送らないようにする CSP を `<meta>` に持ちます。

```sh
floe render docs/spec.yaml                 # docs/spec.html を書く
floe render docs/*.yaml --out-dir site     # site/<名前>.html を書く
floe render --check docs/*.yaml            # CI で：書き直していないページがあれば失敗する
```

| フラグ | 説明 |
|---|---|
| `--out-dir <dir>` | ページを、各データファイルの隣でなく、このディレクトリに書く（無ければ作る）。 |
| `--check` | 何も書かない。無いページと、データファイルが描くものと違うページを出し（終了コード 1）、全部がそのとおりなら、描けたページの警告だけを出す（終了コード 0）。 |

- ページは変わるときだけ書き、そのパスを出します。もう一度走らせても何もしません。
- 描けたページの警告を、`floe check` と同じに stderr に出します。警告は終了コードを変えません。
- あるページは上書きします。取り戻せるように、ページはバージョン管理に置いてください。
- 誤りを `floe check` と同じに出し、全部直すまで何も書きません（終了コード 1）。2 つのデータファイルが同じページを書くとき（1 つの `--out-dir` に `a/spec.yaml` と `b/spec.yaml`、または `spec.yaml` と `spec.yml`）も何も書きません。
- 何も公開せず、サーバーも起こしません。
- 描くのに使えるメモリは `floe check` と同じに 512 MiB までで、全部を描いてから書くので、ページを合わせて数えます。止まったら、一度に渡すファイルを減らしてください。
- ページは、描いた floe・テンプレート・アイコンによります。CI では、ページを書いたときの floe の版とテンプレートを使い、上げたらページを書き直してください。
- ページの `script` は、ファイルを開くとサーバーのページのサンドボックス無しで動きます。それでも CSP が `fetch`・XHR・ほかの所の画像・フォームを止めます。ページの間のリンク（`/a/<slug>/`）はファイルでは働かないので、ファイルどうしを相対でつないでください。

## `floe rebuild`

保存した各ページを、写したデータファイルと画像から、今のテンプレート・部品・テーマでサーバーに描き直させ、変わったページと、保存したページが無くなったページを置き換えます。自分のテンプレート・部品・テーマを変えた後や、floe を上げた後に走らせます。

- 描けなくなったページは前のままにし、誤りを言います（終了コード 1）。元のデータファイルを直してもう一度 publish するか、テンプレートを直してください。1 つのページのメモリか時間（`floe publish` の節）を超えたページもそう言い、ほかのページは描き続けます。
- コマンドを止める（Ctrl+C）と描くのも止まり、まだ描き直していないページは前のままです。もう一度走らせてください。
- リンクしたファイルは開くたびに描くので、触りません。
- サーバーが動いていなければ起こします。

## `floe template list`

floe と自分のテンプレートを 1 行ずつ、タブで区切った 4 列で出します。名前、場所（`floe`、または自分のテンプレートのディレクトリ）、形（データファイルの鍵。下の part list の節）、`schema.json` の説明です。自分のテンプレートは、同じ名前の floe のものを隠します。テンプレートの書き方は [templates.md](agents/templates.md) にあります。

## `floe template new <名前>`

`FLOE_TEMPLATES_DIR` にテンプレート `<名前>` を作ります。`floe template check` が通す最小の `page.html`・`schema.json`・`example.yaml` で、埋めて使います。`page.html` は viewport の `<meta>` も持ち、スマホはページを自分の幅で描きます。作ったディレクトリを `made <パス>` と出します。

- 名前は英小文字・数字・`-`・`_` で、英小文字か数字で始めます。
- 何も上書きしません。その名前のものがあれば、何も作らずに止まります（終了コード 1）。

## `floe template check`

`FLOE_TEMPLATES_DIR` のテンプレートを、自分の部品・テーマとともに `floe part check` と同じに読み、自分の各テンプレートの `example.yaml` を `floe check` と同じに描きます。

- 誤りを出します（終了コード 1）。まずファイルの誤りを出し、ファイルに誤りが無ければ見本を描きます。その後に、描けた見本の警告を出します。正しく、警告も無ければ何も出しません（終了コード 0）。
- テンプレートの中で floe が読まないファイル（`template.yaml` など）は断ります。テンプレートが持つのは `page.html`・`schema.json`・`example.yaml` と、要るなら `page.css`・`computed.yaml`・`checks.yaml`・`words.yaml`・`assets/` です。
- 描くのに使えるメモリは `floe check` と同じに 512 MiB までです。超えると、floe は描くのを止め、描いていたファイルにそれを言います（終了コード 1）。

各ファイルの中身は [templates.md](agents/templates.md) にあります。

## `floe template guide`

自分のテンプレートの作り方 [templates.md](agents/templates.md) を、全部出します。ファイル、それぞれに書くこと、floe が確かめることです。docs そのもので、エージェントがテンプレートを書く前に読みます。引数は取りません。

## `floe part list`

floe のテンプレートの節に書ける部品（floe の `any.json` の鍵と、そこに加わる自分の部品）を 1 行ずつ、タブで区切った 4 列で出します。名前、場所（`floe` か、自分の部品のディレクトリ）、形、説明です。`html` は HTML を字で取り、`schema.json` はありません。`floe part show html any.json` が、鍵 `html` を持つ `any.json` の全体を出します。自分の部品は `any` に加わりますが、`floe part show any any.json` が出すのは、書いてあるとおりの floe の `any.json` です。

形は、その値の書き方です。鍵を名前の順に並べ、項目の並びなら頭に `[] `、どれか 1 つだけを書く鍵なら頭に `one of ` を付けます。字なら format の名前（`markdown`・`html`）、floe の部品そのものなら部品の名前です。`-` は、一覧が言わない形です。`floe part show <名前>`（`template show`・`theme show`）の `files:` の行が読むファイルを名指し、`floe diagram example <種類>` が見本を出し、`floe diagram guide` が図の書き方を言います。テンプレートの形には、どのデータファイルにも書ける `template`・`lang`・`theme`・`title` も入ります。

`--all` を付けると、自分の schema が `$ref` で名指せる部品・見た目・共有の schema を、floe のものも自分のものも、同じ列で出します。場所は `floe` か、自分のもののディレクトリです。`floe:///parts/html.json` は無いので、`html` は入りません。

## `floe part new <名前>`

`FLOE_PARTS_DIR` に部品 `<名前>` を作ります。`floe part check` が通す最小の `schema.json`、箱の `part.html`、空の `part.css` で、埋めて使います。作ったディレクトリを `made <パス>` と出します。

- 何も上書きしません。その名前のものがあれば、何も作らずに止まります（終了コード 1）。

## `floe part check`

`FLOE_PARTS_DIR` の部品・見た目・共有の schema と `FLOE_THEMES_DIR` のテーマを floe のものの上で読み、すべての誤りを出します（終了コード 1）。共有の schema は、どれかの schema が名指すかによらず、その根から確かめます。自分の部品があれば、floe のテンプレートもそれとともにコンパイルします。正しければ何も出しません（終了コード 0）。`floe theme check` も同じです。テーマの `<部品名>.css` は部品があることを前提にするので、部品とテーマは一緒に確かめます。

部品の中身は [parts.md](agents/parts.md)、テーマの中身は [themes.md](agents/themes.md) にあります。

## `floe part guide`

自分の部品・見た目・共有の schema の作り方 [parts.md](agents/parts.md) を、全部出します。ファイル、`part.html` の関数、CSS の層、floe が確かめることです。docs そのもので、エージェントが部品を書く前に読みます。引数は取りません。

## `floe theme list`

テーマを、floe のものも自分のものも 1 行に 1 つずつ、`floe part list` と同じタブ区切りの 4 列で出します。名前、場所（`floe` か、自分のテーマのディレクトリ）、形（テーマは値に書かないので `-`）と、説明（`theme.yaml` の `description:`。無ければ空）です。

## `floe theme new <名前>`

`FLOE_THEMES_DIR` にテーマ `<名前>` を作ります。`floe theme check` が通す最小の、空の `palette.css` で、埋めて使います。floe の `default` のパレット（`floe theme show default palette.css` が出す）の上に重なるので、変えるものだけを書きます。作ったディレクトリを `made <パス>` と出します。

- 何も上書きしません。その名前のものがあれば、何も作らずに止まります（終了コード 1）。

## `floe theme check`

`floe part check` と同じことをします。テーマの `<部品名>.css` は部品があることを前提にするので、部品とテーマは一緒に確かめます。出す誤りも終了コードも同じです。

## `floe theme guide`

自分のテーマの作り方 [themes.md](agents/themes.md) を、全部出します。ファイルと、floe がそれを確かめる決まりです。docs そのもので、エージェントがテーマを書く前に読みます。引数は取りません。

## `floe theme default`

管理ページの設定で選んだ既定のテーマ（テーマを書いていないページが、初めて保存されるときに持つテーマ）の名前を出します。選ばれていなければ何も出しません（そのときは `default`）。`default` を選んでいれば `default` と出します。サーバーを起こさずに、保存先（`FLOE_DIR`）の `settings.json` を読みます。ほかのコマンドが頼む保存先と同じです。`settings.json` の JSON を断るときは、直し方（管理ページの設定で項目を選び直して保存すると、ファイルを書き直す）も言います。

## `floe template show <名前> [ファイル]` / `floe part show <名前> [ファイル]` / `floe theme show <名前> [ファイル]`

floe のものか自分のものの、テンプレート・部品（見た目と共有の schema も）・テーマを出します。それで書く前や、写す前に読むためのものです。名前と説明、場所、読むファイルの並び（`files:`）を出します。ファイルの中身は出しません。

- ファイル名を足すと（`floe part show code part.html`）、そのファイルだけを、先頭の BOM を除いて書いたとおりに出します。floe の部品の `part.html` で、`{{copyButton}}` などの関数の使い方が分かります。読まないファイルの名前は、読むファイルの並びを言って断ります。

| 出すもの | ほかに出すもの | ファイルの順（`files:` の並び） |
|---|---|---|
| テンプレート | データファイルが選べるテーマ（`themes:`） | データファイルが書けるもの（`schema.json`・`checks.yaml`・`computed.yaml`）と `example.yaml`、後に `page.html`・`page.css`・`words.yaml`。`assets/` の画像は出さない |
| 部品 | 借りる見た目 | `schema.json`・`checks.yaml`・`part.yaml`・`part.html`・`part.css`・`words.yaml`。借りる見た目の CSS は、その見た目のもので、`floe part show panel part.css` が出す |
| 見た目 | 借りる見た目 | `part.yaml`・`part.css` |
| 共有の schema | — | `<名前>.json` |
| テーマ | — | `theme.yaml`・`palette.css`・`base.css`・`markdown.css`、その後に部品か見た目ごとの CSS を名前の順で |

## `floe list`

サーバーが並べるとおりに、ページを新しい順に出します（動いていなければ起こす）。各行はタブで区切った 4 列で、更新した日時（手元の時刻、`YYYY-MM-DD HH:MM`）、slug、題、リンクしたパス（保存したページなら空）です。アーカイブしたページは出しません。`--archived` を付けるとそれも出し、どの行にも 5 列目（`archived` か空）を足します。

## `floe info <slug>`

サーバーが持つとおりにページを出します（動いていなければ起こす）。何も書きません。1 行に、名前と値をタブで区切って 1 つずつ出し、毎回同じ 14 個の名前を同じ順に出します。無い値は空です。字の値（`title`・`project`・`task`・`category`・`repository`・`source` と、`tags` の 1 つずつ。タグは空白で並べる）は Go の書き方で引用符に囲み（全角空白などの空白の字はそのまま）、`slug`・`url`・`kind`・`pinned`・`archived`・`version`・`updated` は囲みません。`project` はプロジェクトの無いページでは空で、引用符を外すと `floe task` の `--project` にそのまま渡せます。`kind` は `data`・`link`・`folder` のどれかです。`source` は、データファイルの `repository` の根からのパス（`repository` が空なら実際のパス）か、リンクしたファイル・フォルダの実際のパスです。`version` はリンクでは空です。`updated` は `floe list` と同じ、手元の時刻です。アーカイブしたページも出し、`archived true` と言います。無い slug は断ります。

```text
$ floe info design-notes
slug	design-notes
title	"Design notes"
url	http://127.0.0.1:7325/a/design-notes/
kind	data
project	"floe"
task	"#130"
category	"designs"
pinned	false
tags	"plans" "cli, api"
archived	false
repository	"floe"
source	"docs/design-notes.yaml"
version	3
updated	2026-11-15 10:20
```

## `floe rm <slug>...`

サーバーを通して、ページを順に消します（動いていなければ起こす）。最初の失敗（無いページなど）で止まります。リンクしたファイルそのものは残し、登録だけを消します。

## `floe archive <slug>...`

サーバーを通して、ページを順にアーカイブします（動いていなければ起こす）。最初の失敗（無いページなど）で止まります。アーカイブしたページは、`floe list` と管理ページの一覧に出ません（管理ページでは棚の「アーカイブ」で見られます）。URL では今までどおり開け、ダウンロードでき、`floe rebuild` で描き直されます。アーカイブ済みのページをもう一度アーカイブしても、何も変わりません。`--undo` で一覧に戻します。publish し直しても戻ります。動くのはページだけで、タスクをアーカイブへ移すのは状態です（`floe task --task X --state archived`）。

## `floe tag <slug>... --add <名前> --remove <名前>`

サーバーを通して、ページに順にタグを付け、外します（動いていなければ起こす）。最初の失敗（無いページなど）で止まります。`--add` と `--remove` は名前ごとに 1 回ずつ書き、どちらか 1 つは要ります。名前は書いたとおりに 1 つで、前後の空白だけを落とし、カンマでも分けません。もう付いている名前は 1 つのまま、付いていない名前を外しても何も起きません。`--remove` の名前を先に外し、次に `--add` の名前を付けるので、両方に書いた名前は付いたまま最後に回ります。変わるのは書いた名前だけで、その間に管理ページやほかの `floe tag` が書いたタグは残ります。

```sh
floe tag design-notes plan --add 設計 --add "cli, api"   # 2 つのページに 2 つのタグ
floe tag design-notes --remove 下書き                    # 1 つ外す
```

## `floe task`

プロジェクトの着手前・作業中のタスクを言い、ページがどのタスクにあるかと、タスクの状態を、サーバーを通して書きます（動いていなければ起こす）。タスクはプロジェクトとタスク ID で名指し、floe はどちらの意味も読みません。どのタスクかはページが持ち（各 `meta.json` の `task`。タスクの ID の `name`、カテゴリ、ピン）、タスクのタイトル・状態・外のリンク（複数）・カテゴリの順と、変えた回数（`rev`。画面が送り返し、その後に書かれたタスクへの書き込みは断られます）は保存先の `tasks.json` が持ちます。ページが名指すタスクには必ず行があり、ページのカテゴリは必ずタスクのカテゴリの並びにあります（ページとタスクの 1 回の書き込みが作ります）。`tasks.json` を手で直して行の無いタスクを名指すページは、行にその名前を出し、タスクは一覧に出ません。そのページの task を書く次の書き込み（フラグを付けたページの `floe task --slug`、管理ページの「タスクを設定」・ピン止め・「タスクから外す」の取り消し）が行を作ります。

ページのカテゴリは、タスクのページでタスクのページを分けて並べる所で、カテゴリごとに見出しが付きます。ユーザーが決めます。

```sh
floe task                                                           # プロジェクトの着手前・作業中のタスク。何も書かない
floe task --slug design-notes --task "#130"                         # ページをタスクに載せる
floe task --task "#130" --state doing                               # タスクの状態
floe task --task "#130" --url https://example.com/issues/482        # タスクにリンクを足す
floe task --task "#130" --remove-url https://example.com/issues/482 # 外す
floe task --slug design-notes --category designs                    # タスクの中のページのカテゴリ
floe task --task "#130" --categories proposals --categories designs --categories samples   # カテゴリを見せる順
floe task --slug design-notes --pin                                 # タスクによらずピン止め
floe task --slug design-notes --task "#131" --parent "#130"         # #130 の子のタスクにページを付ける
floe task --task "#130" --forget                                    # タスクの行を消す
floe task --slug design-notes                                       # ページの今を言い、何も書かない
```

書いたタスクとページを 1 行ずつ、store が残した値で言います。タスクは `made`（行が無かった）・`changed`（欄が変わった、ページがそのタスクに来たか、そのタスクの別のカテゴリへ移った）・`unchanged`（欄を書いたが同じ値だった）と書いた欄、ページのカテゴリを足したときはカテゴリの並び、その後にページのタスク・カテゴリ・ピンです。何も変わらず欄も書いていないタスクは言いません。プロジェクトの無いタスクは `in no project` です。タスクに無いページは、`no task` の後にプロジェクトを言い（`page design-notes: no task, in project floe`）、プロジェクトの無いページは `no task` だけです。`--slug` だけでほかのフラグが無ければ、各ページを今の値で同じように言い、何も書きません（ページが名指すタスクに行が無くても、行を作りません）。無いページの `--slug` があれば、どのページも言う前に断ります。`--slug` が無く `--task` だけなら、タスクを今の値（状態と、あれば題・URL・カテゴリ・親。URL とカテゴリは 1 つずつ引用符で `urls "https://…" "https://…"`・`categories "designs" "samples"`、書き込みで最後の 1 つを外したら `no urls`・`no categories`）で言い、何も書きません。行の無いタスクは断ります。

`--project` 以外のフラグが無ければ、プロジェクトの着手前・作業中（状態が `todo` か `doing`）のタスクを、`--task` がタスクを言うのと同じ行で 1 つずつ言い、何も書きません。最後に変えたもの（作った、欄を変えた、ページがそのタスクに来たか、そのタスクの別のカテゴリへ移った。管理ページの「元に戻す」も）が先で、同じ時刻のものは名前順です。完了とアーカイブのタスクは出しません（どの状態のタスクも、`floe task --task <ID>` で言えます）。プロジェクトは、`--project` を省くとカレントディレクトリのもの（`floe publish` がデータファイルのページを入れるプロジェクトと同じ）で、`""` は無しです。`--link` で publish したページは、リンク先のファイルのプロジェクトに入ります。そのプロジェクトは `floe task --slug` と `floe info` が言い、ページが新しいときと移ったときは `floe publish` も言います。着手前・作業中のタスクが無いプロジェクトは `no open task in project floe` と言い、断りではありません。`--task` も `--slug` も無く `--project` 以外のフラグがあれば、名指されていないタスクやページを変えることになるので断ります。

```text
$ floe task
task #130 in project floe: state doing, title "Fix login"
$ floe task --slug design-notes --task "#130"
task #130 in project floe: made
page design-notes: task #130 in project floe
$ floe task --task "#130" --state doing
task #130 in project floe: changed; state doing
$ floe task --slug design-notes
page design-notes: task #130 in project floe
$ floe task --task "#130"
task #130 in project floe: state doing
$ floe task --slug design-notes --task ""
page design-notes: no task, in project floe
$ floe task --task "#130" --forget
task #130 in project floe: forgotten
```

`--slug` を書くと、タスクのプロジェクトは各ページのものです。`--task` は各ページをそれぞれのプロジェクトのその名前に載せ、書かなければ各ページのタスクを変えます。`--project` と `--forget` はタスクだけを名指すので、`--slug` を付けずに使います。`--slug` と一緒の `--parent` は、1 つのプロジェクトのページとだけ使えます。`--slug` を書かないと、`--task` がタスクを名指し、プロジェクトは `--project` です（省くとカレントディレクトリのプロジェクト、`""` は無し）。`--task` も無ければ、`--project` が、着手前・作業中のタスクを言うプロジェクトです。

| フラグ | 変えるもの | |
| --- | --- | --- |
| `--slug <slug>` | ページ | タスクに載せる・変える・言うページの URL 名。何度も書ける。`floe task` は引数を取らない |
| `--task <タスク ID>` | ページか、名指したタスク | `--slug` があるとき、`""` はページをタスクから外し、カテゴリも外す。タスクを変えるもの（`--state`・`--url`・`--remove-url`・`--title`・`--categories`・`--parent`）とも、タスクが要るカテゴリとも一緒に使えない。別のタスクから移したページは、そのタスクと、`--category` でカテゴリを書かなければカテゴリからも外れ、ページの行が前にいた所を言う（`; moved from task #1, category "designs"`。外したときは `; off task #1`）。新しいタスク ID は状態 `todo` のタスクになる |
| `--project <プロジェクト>` | 名指したタスク、または出すタスク | `--slug` が無いときだけ。`--task` が名指すタスクのプロジェクト、`--task` が無ければ、着手前・作業中のタスクを出すプロジェクト。書かなければ作業ディレクトリのプロジェクト。`""` はプロジェクト無し |
| `--category <カテゴリ>` | ページ | `--slug` があるときだけで、タスクに付いたページに。タスクのカテゴリの並びに無ければ、同じ書き込みで末尾に足す。`""` で外す |
| `--state <状態>` | タスク | `todo`（未着手）・`doing`（作業中）・`done`（完了）・`archived`（アーカイブ） |
| `--url <URL>` | タスク | 外のリンクを足す（今のものの後ろに）。`http` か `https`。何度も書ける。1 つのタスクに 10 個まで：超える書き込みは断る。手で 10 個を超えたタスクも、ほかの書き込みは通る |
| `--remove-url <URL>` | タスク | リンクを外す。何度も書ける。無いリンクを外しても誤りにならない。`--url` と両方に書いたリンクは残る。行の無いタスクには作らず、そのタスクが無いと言う |
| `--parent <タスク ID>` | タスク | `--slug` と一緒なら `--task` も書き、ページを付ける 1 つのタスクの親になる。同じプロジェクトに行があり、親を持たないタスク。子を持つタスクには付けられない（親子は 1 段だけ）。`""` で外す |
| `--title <タイトル>` | タスク | `""` で外す |
| `--categories <名前>` | タスク | タスクのカテゴリ。1 つごとに繰り返し、カテゴリの順（書いたとおり）にする。並びに無いページのカテゴリは末尾に足し、ページのあるカテゴリを落とすと断る。`""` で全部外す |
| `--pin`・`--unpin` | ページ | `--slug` があるときだけ |
| `--clear` | ページ | タスクから外し、ピン止めも外す。タスクは残す |
| `--forget` | タスク | `--slug` が無いときだけ。ページが載っている間（アーカイブしたページも）と、子のタスクが残っている間は断る |

ページとタスクは 1 回の書き込みで書きます。先に全部を確かめ（無いページ、タスクを変えるフラグかカテゴリがあるのにタスクの無いページ、ページのあるカテゴリを落とす `--categories`）、断るときは何も書きません。その後に `tasks.json`、ページの順に書きます。その途中でシステムがページを書けなければそこで止まり、タスクとそれより前のページは書かれたまま残るので、同じコマンドをもう一度打つと揃います。ページが付くタスクに行が無ければ作り（`made`）、ページのカテゴリがタスクのカテゴリの並びに無ければ末尾に足します。`floe publish --move-project` や管理ページの「編集」でページのプロジェクトが変わると、ページはタスクから外れます。タスクはプロジェクトの中のもので、別のプロジェクトの同じ名前のタスクは別のタスクだからです。

タスク一覧は、サーバーの `/tasks` で、1 つのプロジェクトのタスクを状態で分けて並べます。プロジェクトを指さずに開くと、このブラウザで最後に見たプロジェクト（今もあるとき）、無ければ作業中で一番新しく変えたタスクのプロジェクト、無ければ左の列の一番上を選び、URL に書きます。どの状態も最後に変えた新しい順で、ページの数、未読の数、リンクを出し、上にそのプロジェクトのピン止めしたページを出します。ピンの × で、ピン止めを外せます。タスクの無いプロジェクトで最後のピンを外すと、そのプロジェクトは一覧から無くなり、一覧に無いプロジェクトの画面になります。タスクの一覧の置き場所は状態だけで決まり、`archived` のタスクは、ページによらず「アーカイブ」に出ます。切り替えは、タスクが無いときも、ロゴの横に出ます。

**タスクを作成**：タスク一覧の左の列の、プロジェクトの下の「＋ タスク」（狭い画面では「絞り込み」の中）で、今のプロジェクトにタスク ID とタイトルでタスクを作ります。作ると未着手の一覧へ移り、新しい行に色が付きます。すでにある ID を打つと、そのことを言い、「タスクを開く」でそのページへ移ります。どのプロジェクトにもタスクが無い画面にも同じボタンがあり、ページのあるプロジェクトか「未設定」から選びます。ページの無いプロジェクトに作るときは `floe task --project` を使います。アーカイブの一覧と、一覧に無いプロジェクト（URL で指したもの）の画面には出ません。

タスクのページの頭の「編集」は、タスクのタイトル・URL・カテゴリを 1 つのモーダルで書きます。URL は、並びの下の「URL を追加」で開く小さなモーダルに書いて「追加」か Enter で足し、行ごとの × のボタンで外し、カテゴリと同じく行のつまみのドラッグか上へ・下へのボタンで並べ替えます。タスクのページと一覧は、その順で出します。送るのは足した URL と外した URL と、順を変えたときだけその順なので、その間にほかで書いた URL は残ります（順に無い URL は後ろに残ります）。カテゴリは名前を変えず、並べ替える・追加する・削除するだけです。行のつまみをドラッグするか、上へ・下へのボタンで動かし（タッチの画面はボタンだけ）、並びの下の「カテゴリを追加」で開く小さなモーダルに名前を打ち、「追加」か Enter で追加し、行の × のボタンで削除します。削除できるのはページの無いカテゴリだけで、ページ（アーカイブしたページも含みます）のあるカテゴリのボタンは押せません。削除するには、先にページの「…」の「タスクから外す」か「タスクを設定」で、そのカテゴリから外します（アーカイブしたページの「…」にもあります）。並べた順は全部書きます。ページを付けたカテゴリはいつもタスクのカテゴリにあり（付けると足されます）、ページのあるカテゴリを並びから落とすと断られ、モーダルがそう言います。送るのは変えた所だけで、その間にほかが書いていれば断り、変えた所を残してほかを読み直します。その間に削除されたタスクは作り直しません。タスクの行を押すと、タスクのページ（`/tasks?project=…&task=…`）を開きます。ページをカテゴリごとに、`--categories` で書いた順、次に初めて付いた順で並べ、カテゴリの無いページを、あるときだけ先頭の見出し「カテゴリなし」の下に出し、どの組の中でも、アーカイブしたページはほかの後に、薄い字で「アーカイブ済み」を添えて出します。ページの無いカテゴリも見出しにします。「編集」の横の「ページを追加」で、同じプロジェクトのページ（アーカイブしたものを除く）を探し、そのモーダルで選んだカテゴリ（初めは「カテゴリなし」）に付けます。ほかのカテゴリのページはそこから移り、ほかのタスクのページは、移すかをモーダルで聞いて「はい」のときに移ります。上には状態を変えるプルダウン、リンク、完了になるとタスクをアーカイブするボタンがあります（`--state archived` と同じ。ページはそのまま残り、ページは行か `floe archive` で別にアーカイブします）。同じボタンでタスクを戻し、完了に戻ります。タスクのページ・モーダル・一覧からの書き込みは画面が最後に読んだ内容で送り、その間に別のセッションが書いていれば断られ、画面はタスクを読み直します。開いただけでは既読になりません。ページも子も無いタスクのページには「タスクを削除」があり、2 回押すと削除して一覧へ戻ります（`--forget` と同じ道）。ここから全面で開いたページはここへ戻り、ピン止めから開いたページはタスク一覧へ戻ります。`h` と上の帯の「タスク一覧」は、そのプロジェクトの一覧の、タスクの今の状態の所へ戻り、そのタスクの行にフォーカスを置きます。

全面で開いたページにも、帯に「ページ一覧」「タスク一覧」があります（どちらも今の画面の印は付きません）。戻る先は開いた元です。ページ一覧かタスク一覧から開いたときは、帯のその一覧のリンクが戻る先です。タスクのページから開いたときは、ロゴの横にタスク ID を言う戻るリンクがあります。幅が 40rem 以下で帯のリンクが出ないときは、どこから開いても戻るリンクが印だけで出ます。`h` も同じ所へ戻ります。このリンク、`h`、ブラウザの戻るで一覧に戻ると、そのページの行にフォーカスがあり、右に同じ版のページが開きます（未読のままのページは開きません）。ロゴはいつもページ一覧へ行きます。開いた行の中に無いページ（検索や別のタブから開いたページ）は、ページ一覧へ戻ります。

ページの「…」でも同じことができます。ピン止めと外す、タスクを開く、「タスクを設定」でタスク ID、カテゴリ、タイトル（新しいタスクのとき）を書き、「タスクから外す」でページをタスクから外します（トーストの「元に戻す」で、同じタスクとカテゴリに戻ります）。タスク自身のタイトル・URL・カテゴリの順はタスクのページの「編集」で、親はそのページの親子のカードで書きます。候補にはタスクの状態が出て、タスクに入れるとトーストで言い、そのタスクのページへのリンクにします。ほかのタスクに載っているページは、移すかをモーダルで聞き（「いいえ」なら何も書きません）、移したトーストは前のタスクを言います。候補に無いタスク ID は新しいタスクになり、タイトルが要ります。ページ一覧の行には、ページのタスクとピン止めのバッジが出て、押すと移れます。

**子のタスク**：親は `--parent` か、タスクのページで付けます。親も子も無いタスクのページは、頭の下に「親のタスク」と「子のタスク」の 2 段を出し、どちらも右に「＋ 追加」があります。「親のタスク」の「＋ 追加」は、そのプロジェクトの今あるタスクを親にするか、タスク ID とタイトルを書いて新しい親を作り、同じ書き込みで付けます。親のあるタスクでは、そこが「変更」になり、どこから移るかをモーダルが先に言います。親や子の行の右のボタンは、その子を親からすぐ外します（マウスでは行に重ねたときとキーで止まったとき、タッチではいつも見えます）。外したときと親を変えたときは、トーストの「元に戻す」で前の親に戻せます（前の親が親になれるときだけ）。親を持たないタスクのページの「子のタスク」の見出しの右の「＋ 追加」は、タスク ID とタイトルを書いて、ページの無い新しい子を未着手で作ります。そのプロジェクトの今あるタスクを選ぶか同じタスク ID を書くと、そのタスクが今のタイトルのまま子になります。別の親の子ならこの親へ移ると、モーダルが先に言います。子を持つタスクは断ります。親と子は別々のタスクで、一覧にはそれぞれの状態の所に出ます。子の行には親の名前、親の行には子の数が字で出ます。タスクのページは頭の下のカードに、子か親を並べ、行の頭に状態を出します。子は状態の順、その中は最後に変えた新しい順です。押すとそのタスクのページへ移ります（`j` `k` は止まりません）。親の状態を変えても子は変わりません。アーカイブもタスクごとで、「アーカイブ」はそのタスクだけを触り、ページ・親・子は触りません。手で書いた `parent` が決まりに合わないとき（無いタスク、自分、親を持つタスク）は、断らずに親の無いタスクとして出します。ページのプロジェクトを変えてもタスクの行は移らず、親子は元のプロジェクトに残ります。

ページの `task` は、公開し直しても、名前を変えても、描き直しても残ります。読めない `tasks.json` や、ほかの状態、`http`・`https` でない URL を持つ `tasks.json` は断り、上書きしません。手で直してください。floe の知らない鍵、同じ鍵が 2 つ、大文字小文字だけが違う鍵（`Title`）を持つ `tasks.json` も、読まずに断ります。

## `floe task guide`

タスク一覧の読み方、ページのタスクへの載せ方、タスクの変え方 [tasks.md](agents/tasks.md) を、全部出します。タスクが持つもの、コマンド、floe が断るものです。docs そのもので、エージェントがタスクを読み書きする前に読みます。`floe guide` は、タスクモードによらず、これを指します。引数は取りません。

## `floe serve`

サーバーを `127.0.0.1` で、SIGTERM・SIGINT か `floe stop` まで前面で動かします。途中の要求を終えてから（長くて 10 秒）止まります。起きた直後に止めたときは、続いて最初のテンプレート・部品・テーマ・アイコンの読みが終わるのも待ちます。2 回目のシグナルではすぐ終わります。ポートを取ると、標準出力に `serving <保存先> at http://127.0.0.1:7325/` を出し（保存先は `FLOE_DIR`、ポートは `FLOE_PORT` のもの）、ほかは何も出しません。[サーバー](#サーバー) に挙げたコマンドは同じサーバーを裏で起こすので、これは主に、サーバーが起きない理由を見るためのものです（動いているサーバーに起きたことは、その `server.log` にあります）。裏のサーバーが起きなければ、`the server did not start; run "floe serve" to see the error` と言います。前面のサーバーの端末を閉じる（SIGHUP）と、2 回目のシグナルと同じくすぐ終わり、どちらも止まったことを書きません。

## `floe stop`

裏で動くサーバーを止め、止まってから戻ります（すぐ後のコマンドは、自分のサーバーを起こします）。動いていなければ `server is not running` と出し、0 で終わります。

## `floe diagram render <spec.yaml>...`

各図の spec を確かめ、図を順に、inline SVG の 1 つの HTML の断片として標準出力に出します。自分の HTML のページ（`floe publish --link` はファイルをそのまま見せるので、`<!doctype html>` と `<html lang>` を持つ文書の全体）に貼るためのものです。データファイルでは、代わりに `diagram` の部品に spec を書きます（spec の書き方は [diagrams.md](agents/diagrams.md)）。相対パスは作業ディレクトリから読みます。

- spec を図の schema で確かめ、書いた言語ごとに並べて確かめます。はみ出す字、重なる部品やキャンバスからはみ出す部品、箱を通る線、交差 …（確かめることの一覧は [diagrams.md](agents/diagrams.md)）。
- 全部の spec のすべての誤りを、`file:line:column: message`（spec 全体の誤りは `file: message`）で渡した順に出し、全部直すまで何も描きません（終了コード 1）。
- 文は `--lang` の言語で書きます（省けば `en`）。文にその言語が無ければ英語にします。
- 断片は、図だけに当てた `default` のパレットと、図のスタイル（パレットの CSS の変数から色を取る）と、拡大のスクリプトで始まります。図の外のページの色と変数は変わらず、図もページのものを読みません。パレットと `color-scheme: light` を図の根に置くので、ページの `:root` や、図を包む要素（暗いパネルなど）に書いた変数と color-scheme は、図に届きません。図は自分の地にパレットの `--bg`（`default` の `#f4f3f0`）を塗るので、暗いページの上では、下のように図の根に `--bg` を書かない限り、明るい箱になります。ページの色で図を描くときは、パレットの変数を図の根に、どの層（`@layer`）の外にも書きます（`.floe-zoom-tools, .floe-zoom { --accent: …; }`）。断片のパレットは層 `floe.palette` にあり、ページが先に名付けた層より後に来るので、ページの層（Tailwind の `@layer components` など）の中の規則は負け、層の外の規則は勝ちます。スタイルは図と同じ木（文書か、1 つの shadow root）に置きます。shadow root の中の図には色が付きますが、道具の並びと拡大は付きません（スクリプトは文書の中の図だけを探します）。上の `floe publish` の節が勧めるブラウザで見ます。`@scope` を読まないブラウザでは、図に色が付きません。`floe part show diagram part.css` が出す CSS はパレットの変数を読むだけで自分の色を持たないので、パレットの無いページには、その CSS でなく断片のスタイルを使います。原寸より小さく描かれた図は、読む人がボタン、Ctrl / ⌘ + ホイール、ピンチで拡大し、拡大中はドラッグか矢印キーで動かします。ページに 1 回あれば足り、2 回以上あっても害はありません。
- 描くのに使えるメモリは `floe check` と同じに 512 MiB までです。超えると、floe は描くのを止め、描いていたファイルにそれを言います（終了コード 1）。

| フラグ | 説明 |
|---|---|
| `--lang <タグ>` | 図の文を書く言語（`en`・`ja`）。既定は `en`。 |
| `--no-assets` | スタイルと拡大のスクリプトを除いて図を出す。それを持つページ向け。 |

## `floe diagram inspect <spec.yaml|data.yaml>...`

各図を `floe diagram render` と同じに確かめ、各部品の置かれた所を出します。線が狙った行に着いているか、ラベルが狙った範囲に入っているかを、絵を見ずに確かめられます。

```text
page.yaml:8:9: diagram "The API" 560x190
frame "cloud" 20,20 300x150
the heading of frame "cloud" 60,26 74.88x18
the icon of frame "cloud" 20,20 31x31
edge [60,10]→[60,120] M60,10 V120
```

- 根に鍵 `template` があるファイルはデータファイルで、テンプレートの schema で確かめた後の図を、`details`・`tabs`・`columns`・`entries`・`checks`・`options` の項目の `parts` の中も含めて、書いた順に読みます。ほかのファイルは spec です。図の外でも schema が断る誤りがあればファイルごと止まります（その下にあるものについて何も言えないため）。
- 図ごとに、書いた場所（`file:line:column:`。spec は `file:`）、題、キャンバスの大きさの行を出します。その下に 1 行ずつ、部品の範囲、枠の見出し、線の道と両端、ラベルの範囲と、それが入る円を出します。
- 置かれた所は標準出力に、誤りは標準エラーに出し、誤りがあれば終了コードは 1 です。検査で断る図も、参考として出します。直すと部品や線が動くことがあり、誤りのある `graph` は、できた分だけか、丸ごとありません。配置まで届かない図（YAML や schema の誤り、無い `example`）は、1 行も出しません。
- データファイルのテンプレートと部品の checks は走らせず、ページのほかの所（format `html` の項目、画像、部品の関数が断るもの）も確かめません。ページ全体を確かめるのは `floe check` です。自分の部品が `{{diagram}}` で描く図は出ません。`template` を忘れたデータファイルは spec として読み、spec の言葉で断ります。`template` を書いた spec はページとして読みます。
- 描くのに使えるメモリは `floe check` と同じに 512 MiB までです。超えると、floe は描くのを止め、描いていたファイルにそれを言います（終了コード 1）。

## `floe diagram example [種類]`

種類を書かなければ、組み込みの見本を、図の種類ごとに 1 つ（構成図、AWS の構成図、floe が配置する AWS の構成図、クラス図、ER 図、フロー図、ガントチャート、Git のブランチ、組織図、4 象限、シーケンス図、状態遷移図、スイムレーン、年表、ベン図）並べます。各行は、`floe part list` と同じく、タブで区切った種類・場所（`floe`）・形（見本は写すもので値に書かないので `-`）・要約です。種類を書けば、その spec を出します。コメントが、配置に使った格子を説明します。どの見本も確かめを通ります。文は英語と日本語の両方を持ち（`{en: …, ja: …}`）、spec と同じ書き方です。AWS の見本は 2 つとも AWS のアイコンを描くので、`floe icons fetch aws` の後に描いてください。

|---|---|
| `aws` | [AWS Architecture Icons](https://aws.amazon.com/architecture/icons/)。48px のサービスとリソースのアイコン、32px のグループのアイコン。Icon package の zip は約 14MB。 |
| `gcp` | [Google Cloud のプロダクトアイコン](https://cloud.google.com/icons)。中心のプロダクトのアイコン（`gcp/cloud-run`）と、プロダクトの分類のアイコン（`gcp/category/networking`）。Google の手引きでは、ほかのプロダクトは分類のアイコンを使います。zip が 2 つで、合わせて約 1MB。Google が廃止した旧のアイコンは取りません。 |

- その版がすでにあれば、そのままにします。`--force` は取り直します。
- アイコンは丸ごと入れ替えます。失敗すれば前のものが残ります。

| フラグ | 説明 |
|---|---|
| `--force` | その版がすでにあっても取り直す。 |

## `floe icons search <セット> <語>...`

セット（`lucide`・`aws`・`gcp`・`azure`）のアイコンのうち、名前がどの語も含むもの（大文字と小文字は区別しない）を 1 行ずつ出します。`icon` の部品に書く名前（`lucide/…`・`aws/…`・`gcp/…`・`azure/…`）と分類を、タブで区切ります。`lucide` は floe に入っています。[Lucide](https://lucide.dev) 1.72.0（ISC）の 2,052 個の全部（`lucide/users`・`lucide/database`・`lucide/server` など）で、分類は Lucide が付けたもの。取ってこなくても `FLOE_ICONS_DIR` が無くても探せます。線は図の字の色で、`icon` の部品の `tone` を書けばその色で描きます。サービスのよく使う略語（`alb`、`s3`、`gke`、`aks`、`vnet`）や、物の略語（`lucide` の `db`・`person`・`browser`）では、そのサービスのアイコンを先頭に出し、続けてその資源も出します（`s3 bucket`）。フォルダを除いた名前が語とちょうど同じアイコンも先頭に出します（`user` なら `lucide/book-user` より先に `lucide/user`、`server` なら `aws/res/server` が先頭）。略語は floe が短い表で持ち、ほかの語は名前とだけ比べます。略語は名指したセットの中だけで引きます（`k8s` は `aws` なら EKS、`gcp` なら GKE、`azure` なら AKS）。あるクラウドの図に別のクラウドのアイコンを置かないよう、セットは必ず名指します（`floe icons search gcp storage`）。取っていないセットは、その取り方を言います。空白を含む語は、空白で分けた語で探します（`"api gateway"` は `api gateway`）。`gcp` で何も見つからないときは、自分のアイコンを持たない製品をカテゴリのアイコンと製品名のラベルで描くことも言います（Google の手引き。`floe icons search gcp category` で出ます）。

## サーバー

- `floe publish`・`floe rebuild`・`floe list`・`floe rm`・`floe archive`・`floe tag`・`floe task` は、サーバーが動いていなければ起こし、動いていればそれを使います。
- これらはサーバーに、ページを確かめ・保存し・描き・並べ・消すよう頼みます。保存先に書くのはサーバーだけです。publish はデータファイル（とサーバーが求める画像）を送り、サーバーが自分のテンプレート・部品・テーマ・アイコンで確かめて描きます。
- floe を入れ直す（別の版、またはビルドし直したバイナリ）と、次のコマンドが動いているサーバーを止めて自分のものを起こし、標準エラーに `stopping the server on port 7325 (pid 1234), which was of another build of floe, to start this build's` と言います。そのあと新しいサーバーが起きなかったとき、サーバーが止まらなかったときも言います。いくつかが一緒に頼んだときは、サーバーが頼みを受けた 1 つが言います。
- サーバーは `floe stop`、別のビルドのコマンドによる入れ替え、ログアウト、再起動まで動き続けます。
- サーバーは自分に起きたことを、保存先（`FLOE_DIR`）の `server.log` に書きます。起きたこと、止まることとその理由（`floe stop` か別のビルドのコマンド、SIGTERM か SIGINT）、止まったこと、panic した要求（スタック付き）、落ちたときに runtime が書いたもの（この行には時刻も pid も付きません）です。行は `time=` と `pid=` のあとに `key=value` が並ぶ形で、スタックは 1 つの `stack=` の値に、改行を `\n` と書いて入ります。panic した要求には、スタックの場所を言う 500 で答え、サーバーは動き続けます。`server.log` が 1 MiB を超えていれば、次の起動で `server.log.1` に移し、前の `.1` は置き換わります。SIGKILL・SIGHUP・2 回目のシグナル・電源断で終わったサーバーは終わりを書かず、最後の行が、動いていると言う行になります。止まっている途中（途中の要求に長くて 10 秒、起きた直後に止めたときは、その後に最初の読みが終わるまで）のサーバーがあるうちに次のサーバーが起きて server.log を回すと、その最後の行は `server.log.1` に書かれます。`server.log` がふつうのファイル（FIFO・ディレクトリなど）でないと、`floe serve` は始まりません。
- サーバーは、起こしたコマンドの `FLOE_TEMPLATES_DIR`・`FLOE_PARTS_DIR`・`FLOE_THEMES_DIR`・`FLOE_ICONS_DIR` で描きます。1 つのコマンドにでなく、どのコマンドも受け取るシェルの環境に設定してください。
- 違うものを使う `floe publish` と `floe rebuild` は、`floe stop` まで断ります。`floe list`・`floe rm`・`floe archive`・`floe tag`・`floe task` は描かないので、どれでも通ります。ただし、floe を入れ直した後にサーバーを置き換えるものは、新しいサーバーがそのコマンドのもので描くので、違うものでは断ります。
- 1 つのサーバーは、そのポートで 1 つの保存先（`FLOE_DIR`）を配信します。動いている間、ほかの保存先へのコマンドは断り、サーバーが配信している保存先を伝えます（断りの文のパスは、シェルでなく Go の二重引用符で書かれます）。コマンドをそのサーバーに送るなら、`FLOE_DIR` をその保存先にしてください。そのあとは上の行のとおりです（`FLOE_TEMPLATES_DIR` などが違えば断り、別のビルドのサーバーは入れ替わります）。自分の保存先を使うなら、その保存先に別の `FLOE_PORT` を使うか（シェルの環境に置くと、どのコマンドにも渡ります）、`floe stop` を実行してからコマンドをもう一度実行してください。サーバーが伝える保存先がこのシステムの絶対パスでないとき（ポートの先が別のシステムのサーバーのとき。Windows から見た WSL の floe など）は、断りの文は自分の保存先に別の `FLOE_PORT` を使う道だけを言います。
- `127.0.0.1` だけで待ちます。ほかのホスト名（DNS リバインディング対策）と、ほかのサイトからの書き込みは断ります。
- 保存したページは描いたとおりに返し、CSP とサンドボックスを付けます。ページはサンドボックスで動くので、スクリプトは管理ページの API に届きません。枠がページから受けるのは、読んだことと、移ることやモーダルを開くキーだけです。
- publish でデータファイルか画像が変わると、保存したページの新しい版ができます。同じ中身の publish、`floe rebuild`、管理ページでの変更では、版はできません。版は新しいものから 20 まで残り、古いものから消えます。
- 保存先の `reads.json` に、保存したページをどの版まで読んだかを、ページの `meta.json` の `id` ごとに持ちます（リンクとフォルダは持ちません）。`id` は、名前を変えても publish し直しても変わりません。ページを消すときと、別のファイルのページで置き換えるときは、先にその記録を消します。`reads.json` を読めない・書けないときは、削除や publish を断り、何も変えません。floe が初めて書く前からあるページは、読んだものとして扱います。`floe serve` が読めないときは `reads.json.broken` に移して新しく作り、どのページも読んだ扱いになります。中身を残すには手で直します。開いたページが既読になったときのトーストと、ページの「…」のメニューの「未読に戻す」で、開く前の見た目に戻せます。もう一度開くと既読になります。アーカイブしたページは未読になりません。行に点・太字・新しい版の札を出さず、未読の数にも入らず、トーストにも「…」にも「未読に戻す」を出しません。
- データファイルから描いたページのスクリプトは、ページの中身を `fetch`・XHR・ほかの所の画像・フォームで外へ送れません（ダウンロードしたものも）。リンクした HTML は、読むものを読みます。
- ページは URL が名指す所（`/a/<slug>/#part`）で開き、ページの中で動いた先を URL に残すので、URL の写しや読み直しでその所が開きます。
- 管理ページは、ページを 1 つのファイルでダウンロードします。保存したページかリンクしたファイルで、CSP を `<meta>` に入れます。
- 管理ページの設定（一覧の上の帯の右端の歯車。幅が 40rem より広い窓で出ます。ページを全画面で開いたときは出ません）は、項目の一覧（全体テーマ・モード。それぞれ今の値つき）で開きます。行を押すとその設定に進み、見出しの上の「設定」で一覧に戻ります。全体テーマでは既定のテーマを選びます。floe のテーマと自分のテーマを、それぞれのテーマで描いた見本のページのカードから選びます。テーマを書いていないページは、初めて保存するときにそれを持ちます。保存済みのページは変わりません。モードではタスクモードの入・切を選びます。入にすると、`floe guide` が Tasks の節の Ask after publishing を出し、エージェントは新しいページを publish するたびに、どのタスクのどのカテゴリに置くかを聞きます。エージェントが切り替えを知るのは、手引きを読み直したときです。保存先は両方を `settings.json` に持ち、片方を保存してももう片方は変わりません。`settings.json` を読めないと、データファイルから描く新しいページを断ります。どちらかを保存し直すと、書き直して直ります。
- ページの「…」の「編集」で、題と説明を変え、折りたたまれた「URL 名とプロジェクト」の中で URL 名とプロジェクトを変えます。プロジェクトは、その中の「プロジェクト」にプロジェクトの名前を打ち込んで変えます。
- ページの「…」の「テーマ」で、データファイルから描くページ（保存したページとリンク）のテーマを選びます。選んだテーマはそのページだけを描き直し、`--theme` と `theme:` より強く、publish し直しても rebuild しても続き、ほかのファイルのページに置き換える（`--force`）と消えます。最初のカード「このページのテーマを外す」は、外したときに表示するテーマ（`--theme`・`theme:`・初めて保存したときの既定のテーマ）を示し、選ぶとそのテーマに戻ります。そのテーマで描けなければ、ページは前のままです。
- 版が 2 つ以上ある保存したページは、どの 2 つの版の間でも、後の版のページそのもの（テーマも部品もそのまま）の上で違いを見られます。足した字は緑の下線、消えた字は元の場所に赤の打ち消し線で出ます。一覧・節・部品の中で消えたものは、前の版の形のまま、部品の後ろ（残ったものより前にあったものは部品の前）に打ち消し線で出ます。表の消えた行とセルは表の中の元の位置に、番号付きの一覧の項目は元の番号で出ます。変わった図と画像には枠が付き、その下で前の版を開けます。枠は、字の印で違いを見せられない所にだけ付きます。目次には変わった節が並び、`n` `p` で次・前の変わった所へ移ります。ページの上の「差分」から開き、新しい版を初めて開いたときは、前に読んだ版から何節変わったかを知らせます。差分を開いても既読になりません。閉じるとページを開くので既読になります。リンクとフォルダには版がありません。太字やリンクの先、CSS の違いは出ません。字の中の画像は alt で比べます。
- 枠の中のページを印刷すると 1 画面分しか紙に出ず、ページだけを開いて印刷するよう知らせが出ます。
- 管理ページはキーで操作でき、`?` でヘルプが開き、その画面で使えるキーの一覧が出ます。ヘルプのもう 1 つの「ページ一覧について」か「タスク一覧について」は、その画面が何か、画面の言葉が何かを説明します（ページ一覧とページ全面ではページ一覧、タスク一覧とタスクのページではタスク一覧）。一覧の帯の、設定の前の ? のボタンは、そこを開きます（幅が 40rem を超える窓。ページ全面には無い）。`Ctrl+K`（`⌘K`）でページを検索します。一覧では、`j` `k` か `↑` `↓` で行を移り、`Enter` で全画面に開き、`x`（か行のメニューの「選択」）で選択、`f` でお気に入り、`/` で検索欄へ移ります。右に開いている行をもう一度押しても（ダブルクリックでも）全画面に開きます。開いているページは `d` で差分を開きます。全画面では、`j` `k` で開いた行の次・前へ移り、`h` で開いた元へ戻り、`f` でお気に入り、`d` で前に読んだ版からの差分（`n` `p` で次・前の変わった所へ移り、`d` で閉じます）、`/` でページを検索します。ページの中を押した後も、floe が描いたページでは `j` `k` `h` `d` `?` `/` `Ctrl+K` が、リンクした HTML ではページが字のキーを使うことがあるので `Ctrl+K` だけが働きます。

## 環境変数

| 変数 | 説明 |
|---|---|
| `FLOE_DIR` | ページの保存先。既定は `$XDG_DATA_HOME/floe`、無ければ `~/.local/share/floe`。 |
| `FLOE_PORT` | ポート（既定は `7325`）。1〜65535 の 10 進の数。 |
| `FLOE_ICONS_DIR` | `floe icons fetch` がアイコンのセットを 1 つずつディレクトリ（`aws`・`gcp`・`azure`）で置く所。組み込みの `lucide` には要らない。既定は `$XDG_DATA_HOME/floe-icons`、無ければ `~/.local/share/floe-icons`。 |
| `FLOE_TEMPLATES_DIR` | 自分のテンプレートを 1 つずつディレクトリで置く所（[templates.md](agents/templates.md)）。既定は `$XDG_CONFIG_HOME/floe/templates`、無ければ `~/.config/floe/templates`。 |
| `FLOE_PARTS_DIR` | 自分の部品・見た目・共有の schema の置き場所（[parts.md](agents/parts.md)）。既定は `$XDG_CONFIG_HOME/floe/parts`、無ければ `~/.config/floe/parts`。 |
| `FLOE_THEMES_DIR` | 自分のテーマを 1 つずつディレクトリで置く所（[themes.md](agents/themes.md)）。既定は `$XDG_CONFIG_HOME/floe/themes`、無ければ `~/.config/floe/themes`。 |
| `BROWSER` | 新しいページを開くコマンド。既定は macOS では `open`、Windows では既定のブラウザ、ほかは `wslview` か `xdg-open`。 |

`FLOE_*` のディレクトリは絶対パスにします。floe はどこで動かしても 1 つの所を読むので、相対パスは断り、どのシェルも読まなかった `~` で始まるものも断ります（`FLOE_PARTS_DIR is ~/x, a relative path; set it to an absolute path`）。相対の `XDG_DATA_HOME`・`XDG_CONFIG_HOME` は、XDG の決まりどおり無いものとします。

コマンドは、自分が使う設定だけを、使うときに確かめます。設定したディレクトリが使えないとき（ディレクトリでない、読めない・書けない、自分のテンプレート・部品・テーマなら無い）は、変数の名前で断ります。

```text
floe: FLOE_PARTS_DIR is /tmp/t/missing, which cannot be used as a directory (no such file or directory); make it a directory floe can use, or set FLOE_PARTS_DIR to another directory
```

- `FLOE_TEMPLATES_DIR`・`FLOE_PARTS_DIR`・`FLOE_THEMES_DIR` は、ページを描くか自分のものを読むコマンド（`floe check`・`floe render`・`template` と `part` のコマンド、描くサーバー）が使うので、設定したものが無ければそれらを止めます。既定の場所が無ければ、自分のものは無いとし、floe のものだけで描きます。既定の場所があってもディレクトリでなければ断ります。
- `FLOE_DIR` はサーバーと、それを使う [サーバー](#サーバー) に挙げたコマンドが使い、無ければ作ります。`FLOE_ICONS_DIR` は icons のコマンド（無ければ作る）と、アイコンを置いた図（その図の所で）が使います。
- `HOME`（Windows では `USERPROFILE`）が無い（または絶対パスでない）とき、ほかに既定の無いディレクトリは無いものとします。`floe check` は floe のテンプレート・部品・テーマだけで走り、そこに書くコマンド（`floe template new`、`FLOE_DIR` を使う `floe list` …）は変数を設定するよう求めます。
- `FLOE_PARTS_DIR`・`FLOE_THEMES_DIR`・`FLOE_TEMPLATES_DIR` は重ねません。2 つが同じディレクトリか、一方がもう一方の中にあれば（symlink を通しても。まだ無いディレクトリへの symlink は、その先で比べます）、中を読む前に、2 つの変数の名前で断ります。設定したものは、まだ無くても比べます。コマンドは自分が読むものだけを比べ、既定の場所は有るときだけ比べます。`floe part new`・`floe theme new`・`floe template new` は、作るものがほかの種類の置き場所の中に入るか、それを含むなら、作らずに断ります。

```text
floe: FLOE_PARTS_DIR (/tmp/pp) and FLOE_THEMES_DIR (/tmp/pp) are one directory, or one is in the other, where floe would read the files of one as those of the other; make FLOE_PARTS_DIR and FLOE_THEMES_DIR two directories, neither in the other
```

## Windows

floe は Windows 11（amd64・arm64。arm64 はビルドしているが試していない）の NTFS の上で動きます。Windows 10 は対応しません（`NUL.png` のような名前を、Windows 11 はファイルと読み、10 はデバイスと読みます）。ReFS・FAT は試していません。OneDrive のフォルダの中のファイルも、ほかと同じく読み、link できます。「オンラインのみ」のファイルも読めます。floe が読むときに OneDrive がダウンロードします。

- インストール：PowerShell（Windows PowerShell 5.1 か PowerShell 7）で `irm https://raw.githubusercontent.com/sukekyo26/floe/main/install.ps1 | iex` を実行すると、`floe.exe` が `%USERPROFILE%\.local\bin` に入ります。`FLOE_VERSION`・`FLOE_INSTALL_DIR`・`FLOE_INSTALL_TIMEOUT` は `install.sh` と同じです。`FLOE_ADD_TO_PATH=1` を付けるとそのフォルダをユーザーの `Path` に足し、付けなければ `Path` は変えません。ダウンロードが途中で止まった場合、PowerShell 7.4 以降は `FLOE_INSTALL_TIMEOUT` 秒で打ち切ります。Windows PowerShell 5.1 は、設定にかかわらず 5 分で打ち切ります。PowerShell 7.0〜7.3 は打ち切らず、時間切れになったことも表示しません。サーバーが上限より短い間隔で少しずつでも送り続けている間は、どの PowerShell も待ち続けます。
- `floe.exe` には署名していません。出どころは `gh attestation verify floe.exe --repo sukekyo26/floe` で確かめられます。
- 置き場所：Linux と同じく、ホーム（`%USERPROFILE%`。`HOME` は読みません）の下です。ページは `%USERPROFILE%\.local\share\floe`、アイコンのセットは `%USERPROFILE%\.local\share\floe-icons`、自分のテンプレート・部品・テーマは `%USERPROFILE%\.config\floe\templates`・`…\parts`・`…\themes`。`XDG_DATA_HOME`・`XDG_CONFIG_HOME` と `FLOE_*` の設定は Linux と同じく読み、どれもドライブ付きの絶対パスにします（`C:\floe\pages`）。floe は `~` を開かず、PowerShell も引用符の中では開きません。`$env:FLOE_DIR = '~\x'` は断られます（`FLOE_DIR is ~\x, a relative path; set it to an absolute path`）。`"$env:USERPROFILE\x"` と書いてください。
- floe は権限を書きません。既定の場所はプロファイルと同じく自分だけのものですが、ほかの所（`C:\floe`）に置いた `FLOE_*` のディレクトリは、その PC のほかの利用者が読み書きできることがあります。
- floe が開くのは、手元のドライブの上のふつうの名前のものだけです。ネットワークの共有（`\\server\share`、`\\wsl.localhost\…`）、ネットワークドライブ（共有を割り当てた `Z:`）、ドライブ文字の無いフォルダにマウントしたボリューム、デバイス、パイプ、ストリームの名前（`a.yaml:x`）と、それらへのリンクは、データファイル・リポジトリ・保存先・自分のもののディレクトリのどれでも断ります。読むファイルと書く先（保存先、`floe render` の出力先、`floe skill install`、`floe part new` など、`floe icons fetch`）は `this is not on a local drive under an ordinary name: …` で断ります。`FLOE_*` の設定が名指すディレクトリは、その設定の文で断ります（`FLOE_DIR is Z:\x, which cannot be used as a directory (not on a local drive under an ordinary name: Z:); …`）。ただし、アイコン集のディレクトリからアイコンを読むときは、読むファイルと同じ文で断ります。ドライブの今のディレクトリからの相対パス（`C:x`）で渡したもの・リンクしたものも断ります。パスを全部書いてください。プロファイルがネットワークの上にある PC では、`FLOE_*` の設定を手元のドライブにしてください。`floe.exe` も手元のドライブに置いてください。ネットワークドライブの上からは、サーバーを使うコマンドが動きません。
- リンクは、どの OS でも断るものに加えて、ドライブの根（`C:\`）、ホームの直下の隠しの属性が付いたディレクトリ（`.` で始まる名前は、どの OS でも断ります）、アプリのデータのフォルダ（`AppData`）とその下の全部（`%TEMP%` も）を断ります。リンクするファイルはプロジェクトのフォルダに書いてください。
- データファイルの画像のパスには、`\`・`:`・デバイスの名前（`NUL`・`CON`）を書けません。
- ほかのプログラムが中のファイルを開いている間は、ディレクトリの名前を変えられません。ページの URL 名の変更や `floe icons fetch` が `Access is denied` で失敗することがあります。閉じてからもう一度実行してください。
- 設定や既定の場所の所に（その場所そのものとして、またはその途中のフォルダとして）ファイルがあると、読むだけのコマンドはその場所を無いものと読んで、それ無しで進むことがあります。アイコンのコマンドは、そのセットを取っていないと言います。
- 新しいページは既定のブラウザで開きます（`BROWSER` がコマンドを名指していればそれで）。
- WSL の floe が `127.0.0.1:7325` で待っていると、Windows からも届くことがあります。たとえば、ポートを転送するプログラム（WSL を開いた VS Code など）を通って届き、そのときはサーバーを止めても、そのプログラムがポートを持ち続けることがあります。両方で floe を使うなら、片方の `FLOE_PORT` を別のポート（`7326`）にしてください。
- テストは、CI と同じく `TMP`・`TEMP` を `AppData` の外（`C:\floe-tmp`）にして走らせます。`%TEMP%` の下はリンクできないためです。

## 終了コード

| コード | 意味 |
|---|---|
| `0` | 成功 |
| `1` | 失敗と、floe が断る値（断った publish、無いページ、使用中のポート、誤りのあるデータファイルや図の spec、無い見本 …） |
| `2` | floe が読めない、または要るものが足りないコマンドライン（知らないフラグやコマンド、足りない引数） |
