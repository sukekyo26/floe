# コマンド

`floe` の全コマンドのリファレンスです。

## 早見表

| コマンド | 用途 |
|---|---|
| `floe publish <data.yaml>` | データファイルから描いたページを保存し（`--link` なら HTML をその場所のまま登録し）、URL を出す |
| `floe check <data.yaml>...` | データファイルを `floe publish` と同じく検査する。公開はしない |
| `floe list` | ページを新しい順に出す |
| `floe rm <slug>...` | ページを消す |
| `floe serve` | サーバーを前面で動かす |
| `floe stop` | 裏で動いているサーバーを止める |
| `floe diagram render <spec.yaml>...` | 図の spec を検査し、インライン SVG にして出す |
| `floe diagram example [kind]` | 例の spec を一覧する、または 1 つ出す |
| `floe icons fetch <set> [zip-or-url]` | 図の `icon` 部品に使うアイコン集（`aws`）を取得する |
| `floe icons search <word>...` | 名前にすべての語を含む取得済みのアイコンを一覧する |
| `floe version` | 版を出す（`floe --version` でも可） |
| `floe help [command]` | ヘルプを出す（Cobra の組み込み） |

---

## `floe publish <data.yaml>` / `floe publish --link <file.html>`

データファイルからページを描いて保存し、URL（`http://127.0.0.1:7325/a/<slug>/`）を stdout に出します。サーバーが動いていなければ、先に裏で起動します。新しい URL 名はブラウザでも開きます。公開し直したときは開いているタブが自分で再読み込みするので、開きません。

ページはデータファイル（`.yaml`・`.yml`）から描きます。HTML のファイルは保存せず、`--link` で登録してそのまま表示します。相対パスは作業ディレクトリを基準に解決します。

### フラグ

| フラグ | 説明 |
|---|---|
| `--link` | HTML のファイルをその場所のまま登録し、そのまま表示する（[リンク](#リンク)を参照） |
| `--slug <name>` | URL 名。英小文字・数字・ハイフンで 64 文字まで。既定はファイル名で、リンクした `index.html` はディレクトリ名を使う |
| `--title <text>` | 一覧に出すタイトル。既定はデータファイルの `title:` か、リンクしたファイルの `<title>`、無ければ最初の `<h1>`、それも無ければ URL 名。空の値は使い方の誤り |
| `--description <text>` | 一覧に出す説明 |
| `--lang <tag>` | データファイルから描くページの言語（`<html lang>`）。BCP 47 の言語タグ（`en`・`ja`・`pt-BR`）。既定は `en`、その URL 名で前に指定した言語があればそれ。`--link` とは一緒に使えない（リンクしたファイルは中身のまま表示する） |
| `--theme <name>` | ページを描くテンプレートのテーマ。データファイルの `theme:` より優先し、そのときは `theme:` を使わない。既定は `theme:`、無ければ `default`。付けずに公開し直すと `theme:` に戻る。空の値は使い方の誤り。`--link` とは一緒に使えない |
| `--force` | 別のプロジェクトから公開したページや、別のファイルのリンクを置き換える |

### データファイル

データファイルはテンプレートを指定し、テンプレートがそのデータからページを描きます。組み込みのテンプレートは `report` です。見出しの下に節を並べ、節は見出しと部品からなります。部品は Markdown の文章で、Markdown で書けないものは `html` の部品で書きます。

```yaml
template: report               # ページを描くテンプレート
title: チームの wiki の移行
eyebrow: 計画 · 2030-04        # タイトルの上の短い行（任意）
lead: 2 回の週末で移す。   # タイトルの下の 1 文（任意）
sections:
  - heading: 手順
    parts:
      - text: |                # Markdown（表も書ける）。中の生の HTML は出さない
          1. **金曜の夜**に編集を止める。
          2. ページを写す。
      - html: <p class="note warn">止めている間の編集は失われます。</p>   # そのまま入る HTML
```

- `theme:` でテンプレートのテーマを選びます（`default`）。
- `FLOE_TEMPLATES_DIR` に置いた自分のテンプレートは、同じ名前の組み込みのテンプレートの代わりに使われます。書き方は [templates.ja.md](templates.ja.md) にあります。
- ページを描く前に、データをテンプレートのスキーマで検査します。誤りはすべて `ファイル:行:列: メッセージ` の形でまとめて出し、すべて直すまで公開しません（終了コード 1）。テンプレートの指定が無い・知らないテンプレート、テンプレートに無い項目（打ち間違い）、値の型の違い、などです。
- データファイルは、キーと値を書いた YAML の文書 1 つにします。`---` で区切って文書が 2 つ以上あるものや、アンカー・エイリアス・タグを使ったものは断ります。
- ページは公開したときに 1 回だけ描きます。後でデータファイルを直しても、公開し直すまでページは変わりません。

### プロジェクトと上書き

ページは、公開したプロジェクトのものになります。プロジェクトは git の `origin` の URL にあるリポジトリ名、無ければリポジトリのディレクトリ名、それも無ければ作業ディレクトリの名前です。リンクは、ファイルのあるディレクトリから決めます。

- 同じプロジェクトから同じ URL 名で公開すると、上書きします。そのことを stderr に出し（`「plan」を更新しました（前回の公開は …、タイトルは「…」）`）、タイトルが変わっていれば別の `--slug` を勧める警告も出します。終了コードは 0 のままです。
- 別のプロジェクトから公開した URL 名は、`--force` が無ければ断ります。`--force` で置き換えると、前のページの内容は何も引き継ぎません。
- 公開し直しても、管理画面で設定したもの（タイトル・プロジェクト・お気に入り）、説明、言語、作成日時は残ります。`--title`・`--description`・`--lang` を指定すれば、そちらが優先されます。

### リンク

`--link` は、HTML のファイルをその場所のまま、そのまま配信します。floe は周りに何も足さないので、自分で書いたページも、ほかのツールが出したページも、書いたとおりに表示されます。リクエストのたびに読み直すので、ファイルを保存すれば開いているタブも更新されます。相対パスで参照するファイル（CSS・スクリプト・画像）のために、そのディレクトリの配下も配信します。

- 登録できるのは、通常の `.html` / `.htm` ファイルだけです。
- ホーム直下の隠しディレクトリ（設定や鍵の置き場）の中にあるファイルは断ります。
- `/` の直下やホームの直下にあるファイルは、ディレクトリ全体が公開されてしまうので断ります。
- `--slug` を付けずに登録すると、同じファイルの URL 名があればそれを使い、無ければ `name`・`name-2`・`name-3` … のうち空いている最初のものを使います。
- 別のファイルが使っている URL 名は、`--force` が無ければ断ります。

## `floe check <data.yaml>...`

データファイルを、`floe publish` がページを保存する前に行うのと同じく検査します。YAML、テンプレートとテーマ、テンプレートのスキーマ・関係の検査・計算、ページの描画です。相対パスは作業ディレクトリを基準に解決します。

- すべてのファイルの誤りを、指定した順にまとめて `ファイル:行:列: メッセージ` の形で出します（終了コード 1）。
- どのファイルも正しければ何も出しません（終了コード 0）。
- 公開もサーバーの起動もしないので、データファイルを置いたリポジトリの CI から使えます。
- データファイル（`.yaml`・`.yml`）でないファイルは断ります。

## `floe list`

ページを新しい順に出します。各行はタブ区切りの 4 列で、更新日時（ローカル時刻、`YYYY-MM-DD HH:MM`）、URL 名、タイトル、リンクのパス（保存したページは空）です。

## `floe rm <slug>...`

指定した順にページを消します。失敗したところ（無いページなど）で止まります。リンクは登録を消すだけで、ファイル自体は残ります。

## `floe serve`

サーバーを前面で動かし、`127.0.0.1` で SIGTERM か SIGINT を受けるまで配信します。`floe publish` も同じサーバーを裏で起動するので、主にエラーを確かめるときに使います。

## `floe stop`

裏で動いているサーバーを止めます。動いていなければ「サーバーは動いていません」と出し、終了コード 0 で終わります。

## `floe diagram render <spec.yaml>...`

図の spec を 1 つずつ検査し、図を渡した順に、ページに貼れるインライン SVG の HTML 断片 1 つにまとめて stdout に出します。`floe publish --link` はファイルを中身のまま表示するので、貼る先は `<!doctype html>` と `<html lang>` を持つ HTML 文書にしてください。相対パスは作業ディレクトリを基準に解決します。

- spec の形の誤り（知らないキー、型の誤り、使えない値）は、その spec の最初の 1 件で止まります。
- 配置の誤りはすべて報告します。文字が箱の幅や高さに収まらない、部品がキャンバスからはみ出す・重なる・枠の境界をまたぐ、線が箱・ラベル・枠の見出しを通る、線同士が X 字に交差する、の各誤りです。
- すべての spec の誤りを `ファイル:行:列: 誤り` の形で出し、すべて直るまで何も描きません（終了コード 1）。
- 一緒に描く図の id は、線の端の記号やアイコンの名前に使うので、互いに違う必要があります。1 ページの図は 1 回の `render` で描いてください。
- 断片の先頭には assets が付きます。図のスタイル（色は `report` のテーマが定める CSS 変数から取るので、ダークモードに追従します。その変数の無いページでは、そのテーマの明るい配色になります）と、図を拡大・縮小するスクリプトです。図は枠に入り、最初は全体が見える大きさで出ます。読む人はボタン・Ctrl / ⌘ + ホイール・ピンチで拡大し、拡大中はドラッグか矢印キーで移動できます。ツールバーの文言はページの言語（`<html lang>`）で出ます。assets は 1 ページに 1 回あれば足り、2 回以上入っても害はありません。

| フラグ | 説明 |
|---|---|
| `--no-assets` | assets を付けずに図だけを出す。すでに assets を持つページに足すとき |

### spec

spec は図を 1 つ持つ YAML ファイルです。キャンバスと、その上に絶対座標（左上が 0, 0）で置く部品を書きます。

```yaml
id: api                        # 英小文字・数字・ハイフン
width: 640
height: 200
title: How the API is laid out # スクリーンリーダーが読み上げる
parts:
  - frame: { x: 16, y: 16, w: 608, h: 168, label: VPC }
  - box: { x: 40, y: 72, w: 200, h: 56, tone: accent, rows: [[ALB, main code], public entry] }
  - box: { x: 400, y: 72, w: 200, h: 56, rows: [API server, ECS] }
  - edge: { d: "M240,100 H400", label: HTTPS, at: [320, 100] }
```

部品は、種類の名前を 1 つのキーにして書きます。括弧の中は既定値です。`tone` は `accent`・`good`・`warn`・`bad` のどれかです。

| 部品 | キー |
|---|---|
| `frame` | `x` `y` `w` `h`、`label`、`accent`、`square`（角を丸めない）、`icon`（`aws/group/region` のようなアイコン名。AWS のグループ枠の作法で、角を丸めず、角に 32px のアイコンを置く。ほかの部品や線はこのアイコンに重ねられない）。見出しは左上の内側に入るので、中身は上端から 32 以上（アイコン付きは 40 以上）下に置く |
| `box` | `x` `y` `w` `h`、`rows`、`tone`、`shape`（`rect`。ほかに `pill`、判定の `hex`、`state`）。行は文字列か `[文字列, スタイル]` で、スタイルは `main`・`sub`・`main code`・`sub code`。スタイルが無ければ 1 行目が `main`、残りが `sub` |
| `table` | `x` `y` `w`、`title`、`rows`、`tone`。行は名前・`[名前]`・`[名前, 型]` か、区切り線の `---`。高さは 30 に、行ごとに 22・区切りごとに 9 を足し、行があればさらに 6 を足したもの。行 i（0 始まり、区切りを除く）の中心は `y + 41 + 22i` |
| `icon` | `x` `y`（左上）、`name`、`label`（アイコンの下に置く）、`size`（48）。`name` はアイコン集とその中の名前で、`aws/amazon-ec2` のように書く（`floe icons search` で探す）。ダーク用の版があるアイコンは配色に合わせて切り替わる。線はアイコンの辺で止める。知らない名前は誤りとして、近い名前を示す |
| `edge` | `d`、`label` と `at: [x, y]`、`dashed`、`bold`、`tone`、`start`（`none`）、`end`（`arrow`）、`crossing`。`d` には絶対座標の `M`・`H`・`V`・`L` だけを使う。端は `arrow`・`triangle`・`diamond`・`odiamond`・`one`・`many`・`zero-one`・`zero-many`・`none`。`crossing: true` はこの線にほかの線との交差を許す |
| `dot` | `cx` `cy`、`r`（7）、`tone`、`hollow`。線は中心まで引いてよい |
| `bar` | `x1` `x2` `y`、`tone`、`label`（棒の右に置く） |
| `axis` | `x1` `x2` `y`、`ticks: [[x, 文字列], ...]`、`grid`（補助線の上端） |
| `circle` | `cx` `cy` `r`、`tone`（`accent`）。円どうしは重なってよい |
| `label` | `text`、`x` `y`、`anchor`（`middle`。ほかに `start`・`end`）、`plain`（背景なし）、`strong` |
| `line` | `x1` `y1` `x2` `y2`、`kind`（`line`。ほかに `lifeline`・`divider`） |
| `raw` | `svg`。部品で描けない SVG をそのまま出す。検査の対象外 |

## `floe diagram example [kind]`

種類を渡さなければ、組み込みの例を一覧します。例は図の種類（構成図・AWS 構成図・クラス図・ER 図・判定フロー・Git のブランチ図・シーケンス図・状態遷移図・タイムライン・ベン図）ごとに 1 つずつあり、各行はタブ区切りで種類と要約です。種類を渡すと、その spec を出します。spec のコメントに、配置に使った格子の説明があります。どの例も検査を通ります。AWS 構成図の例は AWS アイコンを使うので、`floe icons fetch aws` の後で描いてください。

例は英語版と日本語版があり、図の文字もコメントもその言語で書いてあります。メッセージの言語（`FLOE_LANG`、無ければ `LC_ALL`・`LC_MESSAGES`・`LANG`）に従うので、日本語の環境で例を写すと、図も日本語で書き始められます。その言語で書いていない例は、地域を外した言語（`ja-JP` なら `ja`）、それも無ければ英語で出ます。

| フラグ | 説明 |
|---|---|
| `--lang <tag>` | 例の言語。BCP 47 のタグ（`en`・`ja`）で指定する。地域付きは言語に（`ja-JP` は `ja` に）、例の無い言語は英語に戻る |

## `floe icons fetch <set> [zip-or-url]`

アイコン集を、図の `icon` 部品用に `$FLOE_ICONS_DIR/<set>` に取得します。floe はアイコンを同梱しないので、マシンごとにアイコン集を 1 回取得します。アイコン集は次のとおりです。

| アイコン集 | アイコン |
|---|---|
| `aws` | [AWS Architecture Icons](https://aws.amazon.com/architecture/icons/)。48px のサービスとリソースのアイコン、32px のグループのアイコンと、それぞれのダーク用の版。Icon package の zip は約 14MB |

- zip を渡さなければ、アイコン集の公式ページからパッケージを探して取得します。ブラウザで取得した zip のパスか、その URL を渡すこともできます。相対パスは作業ディレクトリから解決します。
- 同じ版が既にあれば何もしません。`--force` で取り直します。
- 置き換えは丸ごとです。途中で失敗しても前の版が残ります。
- 取得は、30 秒たっても応答が無いか、60 秒データが届かないとあきらめます。遅くても届き続けている間は待ちます。256MB を超えるパッケージと、その中の 1MB を超えるアイコンは断ります。

| フラグ | 説明 |
|---|---|
| `--force` | 同じ版が既にあっても取り直す |

## `floe icons search <word>...`

名前にすべての語を含む取得済みのアイコンを、1 行に 1 つ、`icon` 部品に渡す名前（`aws/…`）とカテゴリのタブ区切りで出します。大文字と小文字は区別しません。

## サーバー

- `floe publish` は、サーバーが動いていなければ起動し、動いていればそれを使います。2 つの publish が同時に起動しようとしても、どちらも立ち上がった方のサーバーを使います。
- floe を入れ直すと（別の版か、ビルドし直したバイナリ）、次の publish が動いているサーバーを入れ替えます。
- サーバーは `floe stop`・ログアウト・再起動まで動き続けます。
- 待ち受けは `127.0.0.1` だけです。ほかのホスト名（DNS rebinding 対策）や、ほかのサイトからの書き込みは断ります。
- ページは sandbox の中で動くので、ページのスクリプトから管理画面の API には届きません。

## 環境変数

| 変数 | 説明 |
|---|---|
| `FLOE_DIR` | ページの保存先。既定は `$XDG_DATA_HOME/floe`、無ければ `~/.local/share/floe`。artifact スキルと同じ形式なので、互いの保存先を読める |
| `FLOE_PORT` | ポート（既定は `7325`）。1 から 65535 の 10 進数 |
| `FLOE_ICONS_DIR` | `floe icons fetch` がアイコン集を置く場所。アイコン集ごとにディレクトリ（`aws`）を作る。既定は `$XDG_DATA_HOME/floe-icons`、無ければ `~/.local/share/floe-icons` |
| `FLOE_TEMPLATES_DIR` | 自分のテンプレートを置く場所。テンプレートごとにディレクトリを作る（[templates.ja.md](templates.ja.md)）。既定は `$XDG_CONFIG_HOME/floe/templates`、無ければ `~/.config/floe/templates` |
| `FLOE_LANG` | メッセージの言語（`en`・`ja`）。無ければ `LC_ALL`、`LC_MESSAGES`、`LANG` の順に見る。カタログの無い言語は飛ばす。既定は英語 |
| `BROWSER` | 新しいページを開くコマンド。既定は macOS なら `open`、それ以外は `wslview` か `xdg-open` |

管理画面は、代わりにブラウザの言語に従います。Cobra 自身のエラー（知らないフラグやコマンド）と `--help` は英語です。

## 終了コード

| コード | 意味 |
|---|---|
| `0` | 成功 |
| `1` | 失敗（断られた公開、無いページ、使われているポート、誤りのあるデータファイルや図の spec など） |
| `2` | 使い方の誤り（知らないフラグやコマンド、引数の不足、空の `--title` や `--theme`、知らない例、BCP 47 の形でない `--lang`） |
