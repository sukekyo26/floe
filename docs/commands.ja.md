# コマンド

`floe` のすべてのコマンドの参照です。データファイルの書き方は [pages.ja.md](pages.ja.md) にあります。

## 早見表

| コマンド | すること |
|---|---|
| `floe publish <data.yaml>` | データファイルから描いたページを保存し（または `--link` でファイルかフォルダをその場で登録し）、URL を出す |
| `floe check <data.yaml>...` | データファイルを、ページを描くとおりに確かめる。何も書かない |
| `floe render <data.yaml>...` | 各データファイルのページを、リポジトリに置く HTML のファイルに書く |
| `floe rebuild` | 保存したページを、今のテンプレート・部品・テーマで描き直す |
| `floe template list` | テンプレートを並べる |
| `floe template show <名前> [ファイル]` | テンプレートのテーマと、読むファイルを全部、書いたとおりに出す。ファイル名を足すとそれだけ |
| `floe template new <名前>` | 埋めて使う自分のテンプレートを作る（floe が受ける最小のものに、viewport を足したもの） |
| `floe template check` | 自分のテンプレートを確かめる |
| `floe part list` | 部品・見た目・共有の schema を並べる |
| `floe part show <名前> [ファイル]` | 部品・見た目・共有の schema と、読むファイルを全部、書いたとおりに出す。ファイル名を足すとそれだけ |
| `floe part new <名前>` | 埋めて使う最小の自分の部品を作る |
| `floe part check` | 自分の部品・見た目・共有の schema・テーマを確かめる |
| `floe theme list` | テーマを並べる |
| `floe theme show <名前> [ファイル]` | テーマと、読むファイルを全部、書いたとおりに出す。ファイル名を足すとそれだけ |
| `floe list` | ページを新しい順に並べる |
| `floe rm <slug>...` | ページを消す |
| `floe archive <slug>...` | ページを消さずに一覧から外す（`--undo` で戻す） |
| `floe serve` | サーバーを前面で動かす |
| `floe stop` | 裏で動くサーバーを止める |
| `floe diagram render <spec.yaml>...` | 図の spec を確かめ、inline SVG で出す |
| `floe diagram inspect <spec.yaml>...` | 図の spec を確かめ、各部品の置かれた所を出す |
| `floe diagram example [種類]` | 見本の spec を並べる、または 1 つ出す |
| `floe icons fetch <セット> [zip か URL]` | 図の `icon` の部品が使うアイコンのセット（`aws`）を手元に置く |
| `floe icons search <語>...` | 取ってきたアイコンのうち、名前がどの語も含むものを並べる |
| `floe completion <シェル>` | シェルの補完のスクリプトを出す（Cobra の組み込み） |
| `floe version` | 版を出す（`floe --version` も） |
| `floe help [コマンド]` | ヘルプを出す（Cobra の組み込み） |

## `floe publish <data.yaml>` / `floe publish --link <file|folder>`

データファイルのページを、そこに書いたテンプレートで描き、描いたとおりに保存して、URL（`http://127.0.0.1:7325/a/<slug>/`）を標準出力に、描いたページの警告を `floe check` と同じに標準エラー出力に出します。サーバーが動いていなければ、先に裏で起こします。新しい slug はブラウザでも開きます（`$BROWSER`、無ければ `open`・`wslview`・`xdg-open`）。もう一度 publish したものは開きません。開いたタブが自分で読み直すからです。

ページはデータファイル（`.yaml`・`.yml`）から描きます。書き方は [pages.ja.md](pages.ja.md) にあります。データファイルは、見せる画像とともに（データファイルが名指すパスで）`FLOE_DIR` の下の `<slug>/source-<id>/data.yaml` に写します。元を失ったら、そこから取り戻せます。publish のたびに新しい写しを書いてから前のものを消すので、失敗した publish はページを前のままに残します。相対パスは作業ディレクトリから読みます。

保存したページは描いたときのままです。テンプレート・部品・テーマを変えても、`floe rebuild` で描き直すまで変わりません。HTML のファイルなど、ほかのファイルは保存しません。そのまま見せるには `--link` で登録します。

### フラグ

| フラグ | 説明 |
|---|---|
| `--link` | ファイルかフォルダをその場で登録する。HTML のファイルはそのまま見せ、データファイルはページを開くたびに描き、フォルダはその下の HTML を並べる（[リンクしたファイル](#リンクしたファイル)）。 |
| `--slug <名前>` | URL の名前。英小文字・数字・ハイフンで 1〜64 字、英小文字か数字で始めて終える。既定はファイルの名前。リンクした `index.html` はそのディレクトリの名前。 |
| `--title <文>` | 一覧の題。既定はデータファイルの `title:`、リンクしたファイルの `<title>`、無ければ最初の `<h1>`、無ければ slug。 |
| `--description <文>` | 一覧に出す説明。 |
| `--theme <名前>` | ページを描くテーマ（パレットと部品の形）。データファイルの `theme:` より強い。既定は `theme:`、無ければ `default`。HTML のファイルの `--link` とは使えない（そのまま見せるため）。 |
| `--force` | ほかのプロジェクトから公開したページや、ほかのファイルへのリンクを置き換える。 |

### プロジェクトと上書き

ページは、publish したプロジェクトに属します。プロジェクトは git の `origin` の URL のリポジトリ名、無ければリポジトリのディレクトリ（worktree は元のチェックアウトと同じ）、無ければ作業ディレクトリの名前です。

- 同じプロジェクトからの同じ slug は、ページを上書きします。標準エラー出力がそう言います（`updated "plan" (last published …, title "…")`）。題が変わっていれば、別の `--slug` を勧める警告を出します。終了コードは 0 のままです。
- ほかのプロジェクトから公開した slug は、`--force` が無ければ断ります。`--force` はページを一から作り直し、前のものは何も残しません。
- もう一度の publish は、管理ページで決めたもの（題・プロジェクト・お気に入り・タグ）、説明、作った日時を保ちます。`--title` と `--description` はそれより強いです。アーカイブしたページは一覧に戻ります。

### リンクしたファイル

`--link` は、ページを保存せず、ファイルをその場で登録します。

- 登録できるのは、ふつうの `.html`・`.htm` のファイル、データファイル（`.yaml`・`.yml`）、フォルダだけです。
- ホームの直下の隠しディレクトリ（設定や鍵がある所）の中のファイルは断ります。
- `/` やホームの直下のファイルは断ります。ディレクトリ全体を配信することになるからです。
- `--slug` の無いリンクは、同じファイルの slug を使い、無ければ `name`・`name-2`・`name-3` … の空いた最初のものを取ります。
- ほかのファイルへの同じ slug は、`--force` が無ければ断ります。

HTML のファイルはそのまま見せます。floe は周りに何も足さないので、自分のページやほかの道具が作ったページが、書いたとおりに出ます。その相対の参照（CSS・スクリプト・画像）のため、ディレクトリの下のファイルも配信します。ファイルを保存すると、開いたタブを読み直します。

リンクしたデータファイルは、リンクしたときの `--theme` で、ページを開くたびに描きます。リポジトリで書いているページを、書きながら読めます。

- リンクするときに `floe check` と同じに確かめ、誤りがあれば断ります。
- データファイル、自分の部品・テーマ・テンプレートを保存したとき、またアイコンを取ってきたとき、開いたタブを読み直します。見せる画像を保存しただけでは読み直しません。データファイルを保存し直すか、タブを読み直してください。
- 誤りがあれば、タブはページの代わりに誤りを見せ、直して保存するとページに戻ります。
- ディレクトリのものは配信しません。画像はページの中にあります。ダウンロードは描いたページで、CSP を `<meta>` に入れます。
- 一覧の題は `title:` で、そのたびに読みます。

リンクしたフォルダは、管理ページの「フォルダ」のタブの 1 行です。その URL（`/a/<slug>/`）は、そのタブをフォルダを開いた形で開きます。

- 行を開くと、フォルダの直下のもの（ディレクトリ、次に HTML のファイル（`.html`・`.htm`）、どちらも名前の順）が出ます。ディレクトリも同じく開け、開いた所だけを読むので、ファイルが何千あるフォルダでも、費用は開いたディレクトリの分だけです。開いた所は URL に残ります。
- `.` で始まる名前（`.git`・`.drafts`）は出しません。フォルダの外へ出る symlink と、ふつうのファイルとディレクトリのほかのものも出しません。ディレクトリへの symlink は開きません。フォルダの下のファイルは、リンクした HTML のファイルのディレクトリと同じ決まりで配信します。
- 1 つのディレクトリで出すのは、名前の順に最初の 1000 項目までです。その下の 1 行が、全部でいくつあるかを言います。
- フォルダのページは枠（`/a/<slug>/?file=<パス>`）でフォルダの題の下に開き、左にフォルダの木（ページのある所を開いた形）が出ます。木の境目を引くか、そこで ← → Home End を押すと幅が変わり（160px から、480px か窓の半分まで）、頭のボタンで隠せます。幅と隠したかはブラウザが覚えます。木を隠したときと狭い画面（木はページの上に重なって開く）では、バーから同じディレクトリのページを選べます。題はファイルの名前で、並べるために中は読みません。
- フォルダの中で足した・消した・名前を変えたものは、次に一覧を読んだときに出ます。お気に入り・アーカイブ・タグ・題はフォルダの行が持ち、中のページは持ちません。
- フォルダは、ファイルのディレクトリと同じ決まりで登録します。`/` やホーム、ホームの直下の隠しディレクトリは断ります。`--theme` は断ります。

## `floe check <data.yaml>...`

各データファイルを、ページを描くとおりに確かめます。YAML、テンプレートとテーマ、テンプレートの schema、checks と計算した値、描いたページです。相対パスは作業ディレクトリから読みます。

- 全部のファイルの誤りを、`file:line:column: message` で、渡した順に出します（終了コード 1）。確かめの 1 つの段の誤りは全部まとめて出し、前の段に誤りがあれば後の段は走りません。読み方は [pages.ja.md](pages.ja.md#誤りの読み方) にあります。
- 描けたページの警告（より良い書き方の勧め）を、誤りの後に `file:line:column: warning: message` で出します。警告は終了コードを変えません。[pages.ja.md](pages.ja.md#警告) にあります。
- どのファイルも正しく、警告も無ければ何も出しません（終了コード 0）。
- 何も書かず、サーバーも起こさないので、リポジトリの CI でデータファイルにかけられます。
- データファイル（`.yaml`・`.yml`）でないファイルは断ります。
- 2 回名指したデータファイル（2 つの glob、シンボリックリンクのディレクトリ越し、macOS で大文字と小文字だけ違う名前）は 1 回だけ確かめ、最初に渡したパスで言います。

## `floe render <data.yaml>...`

各データファイルを描き、ページを `<名前>.html` としてデータファイルの隣に書きます。リポジトリが、エージェントが読み書きするデータファイルと、人が読むページを両方持てます。ページは管理ページがダウンロードするものと同じで、floe 無しで開け、見せるもの（画像、図のスタイルと拡大）を全部持ち、スクリプトが中身を外へ送らないようにする CSP を `<meta>` に持ちます。

```sh
floe render docs/spec.yaml                 # docs/spec.html を書く
floe render docs/*.yaml --out-dir site     # site/<名前>.html を書く
floe render --check docs/*.yaml            # CI で：書き直していないページがあれば失敗する
```

| フラグ | 説明 |
|---|---|
| `--out-dir <dir>` | ページを、各データファイルの隣でなく、このディレクトリに書く（無ければ作る）。 |
| `--check` | 何も書かない。無いページと、データファイルが描くものと違うページを出し（終了コード 1）、全部がそのとおりなら、描けたページの警告だけを出す（終了コード 0）。 |

- ページは変わるときだけ書き、そのパスを出します。もう一度走らせても何もしません。
- 描けたページの警告を、`floe check` と同じに stderr に出します。警告は終了コードを変えません。
- あるページは上書きします。取り戻せるように、ページはバージョン管理に置いてください。
- 誤りを `floe check` と同じに出し、全部直すまで何も書きません（終了コード 1）。2 つのデータファイルが同じページを書くとき（1 つの `--out-dir` に `a/spec.yaml` と `b/spec.yaml`、または `spec.yaml` と `spec.yml`）も何も書きません。
- 何も公開せず、サーバーも起こしません。
- ページは、描いた floe・テンプレート・アイコンによります。CI では、ページを書いたときの floe の版とテンプレートを使い、上げたらページを書き直してください。
- ページの `script` は、ファイルを開くとサーバーのページのサンドボックス無しで動きます。それでも CSP が `fetch`・XHR・ほかの所の画像・フォームを止めます。ページの間のリンク（`/a/<slug>/`）はファイルでは働かないので、ファイルどうしを相対でつないでください。

## `floe rebuild`

保存した各ページを、写したデータファイルと画像から、今のテンプレート・部品・テーマでサーバーに描き直させ、変わったページを置き換えます。自分のテンプレート・部品・テーマを変えた後や、floe を上げた後に走らせます。

- 描けなくなったページは前のままにし、誤りを言います（終了コード 1）。元のデータファイルを直してもう一度 publish するか、テンプレートを直してください。
- リンクしたファイルは開くたびに描くので、触りません。
- サーバーが動いていなければ起こします。

## `floe template list`

floe と自分のテンプレートを 1 行ずつ、タブで区切った 3 列で出します。名前、場所（`floe`、または自分のテンプレートのディレクトリ）、`schema.json` の説明です。自分のテンプレートは、同じ名前の floe のものを隠します。テンプレートの書き方は [templates.ja.md](templates.ja.md) にあります。

## `floe template show <名前>`

データファイルを書く前に読むテンプレートを出します。説明、場所、データファイルが選べるテーマ（`themes:`）、読むファイルの並び（`files:`）と、そのファイルを 1 つずつ `==> ファイル <==` の下に書いたとおりに。先にデータファイルが書けるもの（`schema.json`・`checks.yaml`・`computed.yaml`）と書き始めの `example.yaml`、後に `page.html`・`page.css`・`words.yaml` です。`assets/` の画像は出しません。

- ファイル名を足すと（`floe template show report example.yaml`）、そのファイルだけを、先頭の BOM を除いて書いたとおりに出します。読まないファイルの名前は、読むファイルの並びを言って断ります。
- 出力が長いときは、まず `files:` の行を見て、要るファイルを名前で読んでください。

## `floe template new <名前>`

`FLOE_TEMPLATES_DIR` にテンプレート `<名前>` を作ります。`floe template check` が通す最小の `page.html`・`schema.json`・`example.yaml` で、埋めて使います。`page.html` は viewport の `<meta>` も持ち、スマホはページを自分の幅で描きます。

- 名前は英小文字・数字・`-`・`_` で、英小文字か数字で始めます。
- 何も上書きしません。その名前のものがあれば、何も作らずに止まります（終了コード 1）。

## `floe template check`

`FLOE_TEMPLATES_DIR` のテンプレートを、自分の部品・テーマとともに `floe part check` と同じに読み、自分の各テンプレートの `example.yaml` を `floe check` と同じに描きます。

- 誤りを出します（終了コード 1）。まずファイルの誤りを出し、ファイルに誤りが無ければ見本を描きます。その後に、描けた見本の警告を出します。正しく、警告も無ければ何も出しません（終了コード 0）。
- テンプレートの中で floe が読まないファイル（`template.yaml` など）は断ります。テンプレートが持つのは `page.html`・`schema.json`・`example.yaml` と、要るなら `page.css`・`computed.yaml`・`checks.yaml`・`words.yaml`・`assets/` です。

各ファイルの中身は [templates.ja.md](templates.ja.md) にあります。

## `floe part list`

floe と自分の部品・見た目・共有の schema を 1 行ずつ、タブで区切った 3 列で出します。名前、場所（`floe`、または自分のもののディレクトリ）、説明です。

## `floe part show <名前>`

部品・見た目・共有の schema を出します。説明、場所、借りる見た目、読むファイルの並び（`files:`）と、そのファイルを 1 つずつ `==> ファイル <==` の下に書いたとおりに（部品なら `schema.json`・`checks.yaml`・`part.yaml`・`part.html`・`part.css`・`words.yaml`、見た目なら `part.yaml`・`part.css`、共有の schema なら `<名前>.json`）。借りる見た目の CSS は、その見た目のもので、`floe part show panel` が出します。

- ファイル名を足すと（`floe part show code part.html`）、そのファイルだけを、先頭の BOM を除いて書いたとおりに出します。floe の部品の `part.html` で、`{{copyButton}}` などの関数の使い方が分かります。読まないファイルの名前は、読むファイルの並びを言って断ります。
- 出力が長いときは、まず `files:` の行を見て、要るファイルを名前で読んでください。

## `floe part new <名前>`

`FLOE_PARTS_DIR` に部品 `<名前>` を作ります。`floe part check` が通す最小の `schema.json`、箱の `part.html`、空の `part.css` で、埋めて使います。

- 何も上書きしません。その名前のものがあれば、何も作らずに止まります（終了コード 1）。

## `floe part check`

`FLOE_PARTS_DIR` の部品・見た目・共有の schema と `FLOE_THEMES_DIR` のテーマを floe のものの上で読み、すべての誤りを出します（終了コード 1）。共有の schema は、どれかの schema が名指すかによらず、その根から確かめます。正しければ何も出しません（終了コード 0）。

自分の部品・共有の schema・テーマ・テンプレートの誤りは、ページが使うかどうかによらず、`floe check`・`floe render`・`floe publish` も止めます。`floe part check` と `floe template check` で見てください。部品とテーマの中身は [parts.ja.md](parts.ja.md) にあります。

## `floe theme list`

テーマを、floe のものも自分のものも 1 行に 1 つずつ、`floe part list` と同じタブ区切りの 3 列で出します。名前、場所（`floe` か、自分のテーマのディレクトリ）と、空の説明（テーマは説明を持ちません）です。

## `floe theme show <名前> [ファイル]`

テーマを出します。名前、場所、読むファイルの並び（`files:`）と、そのファイルを 1 つずつ `==> ファイル <==` の下に書いたとおりに。`palette.css`・`base.css`、その後に部品か見た目ごとの CSS を名前の順で。

- ファイル名を足すと（`floe theme show ink note.css`）、そのファイルだけを、先頭の BOM を除いて書いたとおりに出します。読まないファイルの名前は、読むファイルの並びを言って断ります。
- 出力が長いときは、まず `files:` の行を見て、要るファイルを名前で読んでください。

## `floe list`

サーバーが並べるとおりに、ページを新しい順に出します（動いていなければ起こす）。各行はタブで区切った 4 列で、更新した日時（手元の時刻、`YYYY-MM-DD HH:MM`）、slug、題、リンクしたパス（保存したページなら空）です。アーカイブしたページは出しません。`--archived` を付けるとそれも出し、どの行にも 5 列目（`archived` か空）を足します。

## `floe rm <slug>...`

サーバーを通して、ページを順に消します（動いていなければ起こす）。最初の失敗（無いページなど）で止まります。リンクしたファイルそのものは残し、登録だけを消します。

## `floe archive <slug>...`

サーバーを通して、ページを順にアーカイブします（動いていなければ起こす）。最初の失敗（無いページなど）で止まります。アーカイブしたページは、`floe list` と管理ページの一覧に出ません（管理ページでは棚の「アーカイブ」で見られます）。URL では今までどおり開け、ダウンロードでき、`floe rebuild` で描き直されます。アーカイブ済みのページをもう一度アーカイブしても、何も変わりません。`--undo` で一覧に戻します。publish し直しても戻ります。

## `floe serve`

サーバーを `127.0.0.1` で、SIGTERM・SIGINT か `floe stop` まで前面で動かします。途中の要求を終えてから（長くて 10 秒）止まり、2 回目のシグナルではすぐ終わります。`floe publish`・`floe rebuild`・`floe list`・`floe rm`・`floe archive` は同じサーバーを裏で起こすので、これは主にサーバーの誤りを見るためのものです。裏のサーバーが起きなければ、`the server did not start; run "floe serve" to see the error` と言います。

## `floe stop`

裏で動くサーバーを止め、止まってから戻ります（すぐ後のコマンドは、自分のサーバーを起こします）。動いていなければ `server is not running` と出し、0 で終わります。

## `floe diagram render <spec.yaml>...`

各図の spec を確かめ、図を順に、inline SVG の 1 つの HTML の断片として標準出力に出します。自分の HTML のページ（`floe publish --link` はファイルをそのまま見せるので、`<!doctype html>` と `<html lang>` を持つ文書の全体）に貼るためのものです。データファイルでは、代わりに `diagram` の部品に spec を書きます（spec の書き方は [pages.ja.md](pages.ja.md#図)）。相対パスは作業ディレクトリから読みます。

- spec を図の schema で確かめ、書いた言語ごとに並べて確かめます。はみ出す字、重なる部品やキャンバスからはみ出す部品、箱を通る線、交差 …（確かめることの一覧は [pages.ja.md](pages.ja.md#図)）。
- 全部の spec のすべての誤りを、`file:line:column: message` で渡した順に出し、全部直すまで何も描きません（終了コード 1）。
- 文は `--lang` の言語で書きます（省けば `en`）。文にその言語が無ければ英語にします。
- 断片は、図のスタイル（パレットの CSS の変数から色を取る。変数の無いページでは `default` の色）と、拡大のスクリプトで始まります。読む人はボタン、Ctrl / ⌘ + ホイール、ピンチで拡大し、拡大中はドラッグか矢印キーで動かします。ページに 1 回あれば足り、2 回以上あっても害はありません。

| フラグ | 説明 |
|---|---|
| `--lang <タグ>` | 図の文を書く言語（`en`・`ja`）。既定は `en`。 |
| `--no-assets` | スタイルと拡大のスクリプトを除いて図を出す。それを持つページ向け。 |

## `floe diagram inspect <spec.yaml>...`

各 spec を `floe diagram render` と同じに確かめ、各部品の置かれた所を 1 行ずつ出します。部品の範囲、線の道と両端、ラベルの範囲と、それが入る円です。描いた図を見ずに、線が意図した行に着くか、ラベルが範囲に収まるかを確かめられます。

## `floe diagram example [種類]`

種類を書かなければ、組み込みの見本を、図の種類ごとに 1 つ（構成図、AWS の構成図、クラス図、ER 図、フロー図、ガントチャート、Git のブランチ、組織図、4 象限、シーケンス図、状態遷移図、スイムレーン、年表、ベン図）並べます。各行は、タブで区切った種類と要約です。種類を書けば、その spec を出します。コメントが、配置に使った格子を説明します。どの見本も確かめを通ります。文は英語と日本語の両方を持ち（`{en: …, ja: …}`）、spec と同じ書き方です。AWS の見本は AWS のアイコンを描くので、`floe icons fetch aws` の後に描いてください。

## `floe icons fetch <セット> [zip か URL]`

図の `icon` の部品のため、アイコンのセットを `FLOE_ICONS_DIR/<セット>` に置きます。floe はアイコンを同梱しないので、マシンごとに 1 回取ってきます。セット：

| セット | アイコン |
|---|---|
| `aws` | [AWS Architecture Icons](https://aws.amazon.com/architecture/icons/)。48px のサービスとリソースのアイコン、32px のグループのアイコン。Icon package の zip は約 14MB。 |

- zip を渡さなければ、セットの公式のページからパッケージを探して取ってきます。ブラウザで取ってきた zip か、その URL を渡すこともできます。相対パスは作業ディレクトリから読みます。
- その版がすでにあれば、そのままにします。`--force` は取り直します。
- アイコンは丸ごと入れ替えます。失敗すれば前のものが残ります。

| フラグ | 説明 |
|---|---|
| `--force` | その版がすでにあっても取り直す。 |

## サーバー

- `floe publish`・`floe rebuild`・`floe list`・`floe rm`・`floe archive` は、サーバーが動いていなければ起こし、動いていればそれを使います。
- これらはサーバーに、ページを確かめ・保存し・描き・並べ・消すよう頼みます。保存先に書くのはサーバーだけです。publish はデータファイル（とサーバーが求める画像）を送り、サーバーが自分のテンプレート・部品・テーマ・アイコンで確かめて描きます。
- floe を入れ直す（別の版、またはビルドし直したバイナリ）と、次のコマンドが動いているサーバーを入れ替えます。
- サーバーは `floe stop`、ログアウト、再起動まで動き続けます。
- サーバーは、起こしたコマンドの `FLOE_TEMPLATES_DIR`・`FLOE_PARTS_DIR`・`FLOE_THEMES_DIR`・`FLOE_ICONS_DIR` で描きます。違うものを使う `floe publish` と `floe rebuild` は `floe stop` まで断るので、1 つのコマンドにでなく、どのコマンドも受け取るシェルの環境に設定してください。`floe list`・`floe rm`・`floe archive` は描かないので、どれでも通ります。ただし、floe を入れ直した後に動いているサーバーを置き換えるときは、新しいサーバーがそのコマンドのものを使って描くので、`floe publish` と同じく、違うものでは断ります。
- 1 つのサーバーは、そのポートで 1 つの保存先（`FLOE_DIR`）を配信します。動いている間、ほかの保存先へのコマンドは断ります。その保存先には別の `FLOE_PORT` を使ってください。
- `127.0.0.1` だけで待ちます。ほかのホスト名（DNS リバインディング対策）と、ほかのサイトからの書き込みは断ります。
- 保存したページは描いたとおりに返し、CSP とサンドボックスを付けます。ページはサンドボックスで動くので、スクリプトは管理ページの API に届きません。
- データファイルから描いたページのスクリプトは、ページの中身を `fetch`・XHR・ほかの所の画像・フォームで外へ送れません（ダウンロードしたものも）。リンクした HTML は、読むものを読みます。
- ページは URL が名指す所（`/a/<slug>/#part`）で開き、ページの中で動いた先を URL に残すので、URL の写しや読み直しでその所が開きます。
- 管理ページは、ページを 1 つのファイルでダウンロードします。保存したページかリンクしたファイルで、CSP を `<meta>` に入れます。

## 環境変数

| 変数 | 説明 |
|---|---|
| `FLOE_DIR` | ページの保存先。既定は `$XDG_DATA_HOME/floe`、無ければ `~/.local/share/floe`。 |
| `FLOE_PORT` | ポート（既定は `7325`）。1〜65535 の 10 進の数。 |
| `FLOE_ICONS_DIR` | `floe icons fetch` がアイコンのセットを 1 つずつディレクトリ（`aws`）で置く所。既定は `$XDG_DATA_HOME/floe-icons`、無ければ `~/.local/share/floe-icons`。 |
| `FLOE_TEMPLATES_DIR` | 自分のテンプレートを 1 つずつディレクトリで置く所（[templates.ja.md](templates.ja.md)）。既定は `$XDG_CONFIG_HOME/floe/templates`、無ければ `~/.config/floe/templates`。 |
| `FLOE_PARTS_DIR` | 自分の部品・見た目・共有の schema の置き場所（[parts.ja.md](parts.ja.md)）。既定は `$XDG_CONFIG_HOME/floe/parts`、無ければ `~/.config/floe/parts`。 |
| `FLOE_THEMES_DIR` | 自分のテーマを 1 つずつディレクトリで置く所（[parts.ja.md](parts.ja.md)）。既定は `$XDG_CONFIG_HOME/floe/themes`、無ければ `~/.config/floe/themes`。 |
| `BROWSER` | 新しいページを開くコマンド。既定は macOS では `open`、ほかは `wslview` か `xdg-open`。 |

`FLOE_*` のディレクトリは絶対パスにします。floe はどこで動かしても 1 つの所を読むので、相対パスは断り、どのシェルも読まなかった `~` で始まるものも断ります（`FLOE_PARTS_DIR is ~/x, a relative path; set it to an absolute path`）。相対の `XDG_DATA_HOME`・`XDG_CONFIG_HOME` は、XDG の決まりどおり無いものとします。

コマンドは、自分が使う設定だけを、使うときに確かめます。設定したディレクトリが使えないとき（ディレクトリでない、読めない・書けない、自分のテンプレート・部品・テーマなら無い）は、変数の名前で断ります。

```text
floe: FLOE_PARTS_DIR is /tmp/t/missing, which cannot be used as a directory (no such file or directory); make it a directory floe can use, or set FLOE_PARTS_DIR to another directory
```

- `FLOE_TEMPLATES_DIR`・`FLOE_PARTS_DIR`・`FLOE_THEMES_DIR` は、ページを描くか自分のものを読むコマンド（`floe check`・`floe render`・`template` と `part` のコマンド、描くサーバー）が使うので、設定したものが無ければそれらを止めます。既定の場所が無ければ、自分のものは無いとし、floe のものだけで描きます。既定の場所があってもディレクトリでなければ断ります。
- `FLOE_DIR` はサーバー（`floe serve` と、それを起こす `floe publish`・`floe rebuild`・`floe list`・`floe rm`・`floe archive`）が使い、無ければ作ります。`FLOE_ICONS_DIR` は icons のコマンド（無ければ作る）と、アイコンを置いた図（その図の所で）が使います。
- `HOME` が無い（または絶対パスでない）とき、ほかに既定の無いディレクトリは無いものとします。`floe check` は floe のテンプレート・部品・テーマだけで走り、そこに書くコマンド（`floe template new`、`FLOE_DIR` を使う `floe list` …）は変数を設定するよう求めます。
- `FLOE_PARTS_DIR`・`FLOE_THEMES_DIR`・`FLOE_TEMPLATES_DIR` は重ねません。2 つが同じディレクトリか、一方がもう一方の中にあれば（symlink を通しても）、中を読む前に、2 つの変数の名前で断ります。設定したものは、まだ無くても比べます。コマンドは自分が読むものだけを比べ、既定の場所は有るときだけ比べます。`floe part new`・`floe template new` は、作るものがほかの種類の置き場所の中に入るか、それを含むなら、作らずに断ります。

```text
floe: FLOE_PARTS_DIR (/tmp/pp) and FLOE_THEMES_DIR (/tmp/pp) are one directory, or one is in the other, where floe would read the files of one as those of the other; make FLOE_PARTS_DIR and FLOE_THEMES_DIR two directories, neither in the other
```

コマンドラインは、環境の言語によらず英語で話します。管理ページと、データファイルの誤りのページは、ブラウザの言語に従います。

## 終了コード

| コード | 意味 |
|---|---|
| `0` | 成功 |
| `1` | 失敗と、floe が断る値（断った publish、無いページ、使用中のポート、誤りのあるデータファイルや図の spec、無い見本 …） |
| `2` | floe が読めない、または要るものが足りないコマンドライン（知らないフラグやコマンド、足りない引数） |
