# コマンド

`floe` のすべてのコマンドの参照です。データファイルの書き方は [pages.ja.md](pages.ja.md) にあります。

## 早見表

| コマンド | すること |
|---|---|
| `floe guide` | エージェント向けの手引き（ページの書き方・検査・出し方）を出す |
| `floe skill install <agent>` | 名指したエージェントに、`floe guide` を指すスキルを書く |
| `floe publish <data.yaml>` | データファイルから描いたページを保存し（または `--link` でファイルかフォルダをその場で登録し）、URL を出す |
| `floe check <data.yaml>...` | データファイルを、ページを描くとおりに確かめる。何も書かない |
| `floe render <data.yaml>...` | 各データファイルのページを、リポジトリに置く HTML のファイルに書く |
| `floe rebuild` | 保存したページを、今のテンプレート・部品・テーマで描き直す |
| `floe template list` | テンプレートを並べる |
| `floe template show <名前> [ファイル]` | テンプレートのテーマと、読むファイルの並びを出す。ファイル名を足すと、そのファイルを書いたとおりに |
| `floe template new <名前>` | 埋めて使う自分のテンプレートを作る（floe が受ける最小のものに、viewport を足したもの） |
| `floe template check` | 自分のテンプレートを確かめる |
| `floe part list [--all]` | floe のテンプレートの節に書ける部品を並べる。`--all` は部品・見た目・共有の schema を全部 |
| `floe part show <名前> [ファイル]` | 部品・見た目・共有の schema（`html` なら `any.json`）と、読むファイルの並びを出す。ファイル名を足すと、そのファイルを書いたとおりに |
| `floe part new <名前>` | 埋めて使う最小の自分の部品を作る |
| `floe part check` | 自分の部品・見た目・共有の schema・テーマを確かめる |
| `floe theme list` | テーマを並べる |
| `floe theme show <名前> [ファイル]` | テーマと、読むファイルの並びを出す。ファイル名を足すと、そのファイルを書いたとおりに |
| `floe theme default` | 管理ページの設定で選んだ既定のテーマを出す |
| `floe list` | ページを新しい順に並べる |
| `floe rm <slug>...` | ページを消す |
| `floe archive <slug>...` | ページを消さずに一覧から外す（`--undo` で戻す） |
| `floe tag <slug>... --add <名前> --remove <名前>` | ページにタグを付ける・外す |
| `floe work [<slug>...]` | ページのタスク・カテゴリ・ピンを言う。ページをタスクに載せる、ピン止めする、タスクを変える |
| `floe serve` | サーバーを前面で動かす |
| `floe stop` | 裏で動くサーバーを止める |
| `floe diagram render <spec.yaml>...` | 図の spec を確かめ、inline SVG で出す |
| `floe diagram inspect <spec.yaml\|data.yaml>...` | spec かデータファイルの図を確かめ、各部品の置かれた所を出す |
| `floe diagram example [種類]` | 見本の spec を並べる、または 1 つ出す |
| `floe diagram guide` | 図の書き方（手書きか graph か）を出す |
| `floe icons fetch <セット> [zip か URL]` | 図の `icon` の部品が使うアイコンのセット（`aws`）を手元に置く |
| `floe icons search <語>...` | 取ってきたアイコンのうち、名前がどの語も含むものを並べる（`alb` のような略語でも探せる） |
| `floe completion <シェル>` | シェルの補完のスクリプトを出す（Cobra の組み込み） |
| `floe version` | 版を出す（`floe --version` も） |
| `floe help [コマンド]` | ヘルプを出す（Cobra の組み込み） |

## `floe guide`

エージェント向けの手引き [guide.ja.md](guide.ja.md)（英語の guide.md を出す）を出します。ページの書き方・検査・出し方、テンプレートと部品の選び方、floe が書いたとおりに読む YAML、誤りの読み方です。この docs の要約で、エージェントがページを書く前に読みます。引数は取りません。

## `floe skill install <agent>`

floe のスキル `floe/SKILL.md` を、名指したエージェントが全部のプロジェクトのスキルを読む所に書きます。エージェントと置き場所は `floe skill install --help` が並べます。スキルはエージェントに `floe guide` を走らせるよう言うだけなので、floe を上げても古くなりません。書いたパスを、リンクをたどった後の形で出します。この floe の `SKILL.md` があればそのままにし、別のものは残して、`--force` のときだけ上書きします。リンク `floe` は `floe` という名前のディレクトリへ、リンク `SKILL.md` は `SKILL.md` という名前のファイルへだけたどります（`floe render` がページのリンクを `.html` のファイルへだけたどるのと同じ）。`CLAUDE_CONFIG_DIR` を設定していると、`claude` はその下に書きます。そこのディレクトリが使えなければ設定の誤りとして、その下のファイルの誤りはそのパスで言います。

## `floe publish <data.yaml>` / `floe publish --link <file|folder>`

データファイルのページを、そこに書いたテンプレートで描き、描いたとおりに保存して、URL（`http://127.0.0.1:7325/a/<slug>/`）を標準出力に、描いたページの警告を `floe check` と同じに標準エラー出力に出します。走らせたディレクトリがページのプロジェクトを決めたとき（ページが新しい、またはプロジェクトが変わったとき）は、それを言う 1 行（`page in project floe`、無ければ `page in no project`）も標準エラー出力に出します。サーバーが動いていなければ、先に裏で起こします。新しい slug はブラウザでも開きます（`$BROWSER`、無ければ `open`・`wslview`・`xdg-open`）。もう一度 publish したものは開きません。開いたタブが自分で読み直すからです。

ページはデータファイル（`.yaml`・`.yml`）から描きます。書き方は [pages.ja.md](pages.ja.md) にあります。データファイルは、見せる画像とともに（データファイルが名指すパスで）`FLOE_DIR` の下の `<slug>/source-<id>/data.yaml` に写します。元を失ったら、そこから取り戻せます。publish のたびに新しい写しを書いてから前のものを消すので、失敗した publish はページを前のままに残します。相対パスは作業ディレクトリから読みます。

保存したページは描いたときのままです。テンプレート・部品・テーマを変えても、`floe rebuild` で描き直すまで変わりません。テーマを書いていないページは、初めて保存したときに管理ページの設定で選ばれていた既定のテーマを持ち続けます。既定を変更しても、変わるのはその後に保存するページだけです。管理ページでページの「…」の「テーマ」から選んだテーマは、そのページをすぐ描き直し、どれよりも強く、publish し直しても続きます。HTML のファイルなど、ほかのファイルは保存しません。そのまま見せるには `--link` で登録します。

### フラグ

| フラグ | 説明 |
|---|---|
| `--link` | ファイルかフォルダをその場で登録する。HTML のファイルはそのまま見せ、データファイルはページを開くたびに描き、フォルダはその下の HTML を並べる（[links.ja.md](links.ja.md)）。 |
| `--slug <名前>` | URL の名前。英小文字・数字・ハイフンで 1〜64 字、英小文字か数字で始めて終える。既定は、そのファイルのページの URL 名、無ければファイルの名前。リンクした `index.html` はそのディレクトリの名前。 |
| `--title <文>` | 一覧の題。既定はデータファイルの `title:`、リンクしたファイルの `<title>`、無ければ最初の `<h1>`、無ければ slug。 |
| `--description <文>` | 一覧に出す説明。 |
| `--theme <名前>` | ページを描くテーマ（パレットと部品の形）。データファイルの `theme:` より強い。管理ページでページに選んだテーマは、これより強い。既定は `theme:`、無ければ初めて保存したときの既定のテーマ、無ければ `default`。HTML のファイルやフォルダの `--link` とは使えない（そのまま見せるため）。 |
| `--force` | ほかのファイルのページ、ほかのファイルへのリンクを置き換える。前のものは、ページの前の版も含めて何も残さない。 |
| `--move-project` | ページがすでに別のプロジェクトに入っていても、`floe publish` を走らせたディレクトリのプロジェクトに入れる。付けなければ、ページは前のプロジェクトを保つ。`--link` とは使えず（互いに排他のフラグ）、そのディレクトリにプロジェクトが無いときも断る（ページが扱うリポジトリで走らせるよう、誤りが言う）。名前では指定しない。 |

### プロジェクトと上書き

新しいページは、初めて publish したプロジェクトに入ります。プロジェクトの名前は、`floe publish` を走らせた git リポジトリの `origin` の URL のリポジトリ名、無ければリポジトリのディレクトリ名です（worktree は元のチェックアウトと同じ）。リポジトリの外では、走らせたディレクトリの名前です。データファイルの置き場所は関係ありません。`floe publish` は、ページが新しいとき、またはプロジェクトが変わったとき（`--force` でほかのファイルのページを置き換えたとき、プロジェクトを空にしたページを publish し直したとき）に、ページが入ったプロジェクトを、URL の後に標準エラー出力で言います（`page in project floe`、無ければ `page in no project`）。プロジェクトが変わらない上書きと、`--link`（プロジェクトはリンク先のディレクトリのもの）は、何も言いません。

- ページは、そのデータファイルのものです。ファイルは、そのファイルのリポジトリと、リポジトリの根から見た道で決まり、リポジトリの外なら実体のパスで決まります。どのディレクトリから publish しても同じです。`docs/plan.yaml` は、リポジトリの根から出しても、`docs` から出しても、別の worktree から出しても、リポジトリの外から出しても同じファイルで、出し直してもページのプロジェクトは変わりません（`--move-project` を付けたときを除く）。リポジトリは名前で見分けます。同じ `origin` の 2 つの clone は 1 つのページを使い、名前が同じ 2 つのリポジトリもそうなります。
- 同じファイルからの同じ slug は、ページを上書きします。標準エラー出力がそう言います（`updated "plan" (last updated …, title "…")`）。題が変わっていれば、何から何に変わったかを警告で出します。終了コードは 0 のままです。
- ほかのファイルのページの slug は、`--force` が無ければ断ります。`--force` はページを一から作り直し、前のものは何も残しません。`--force` はページの履歴（版、固定した題、タグ、お気に入り）を捨てます。データファイルを動かしたり名前を変えたりして、同じ URL を使い続けるときは、`--force` で publish してください。`--slug` が無いとき、`--force` が置き換えるのは、そのファイルのページが無いときの、ファイルの名前のページだけです。
- 管理ページで URL 名を変えたページ（`o` を `d` に）は、元のファイルのままです。そのファイルを `--slug` なしで publish し直すと、`d` に書きます。ほかのファイルから `d` に publish すると、`--force` が無ければ断ります。1 つのファイルのページが 2 つあるとき（別の `--slug` で publish するとできます）は、ファイルの名前のページ、無ければ URL 名の順で最初のページに書きます。要らない方は `floe rm` で消してください。
- ページとリンクは、`--force` でも互いの slug を取れません。先に `floe rm` してください。
- もう一度の publish は、ページのプロジェクト（`--move-project` を付けたときは、floe を走らせたディレクトリのプロジェクトに入れます。新しいページの名前の決め方と同じで、間違ったプロジェクトに入ったページを直すためです。`--link` とは使えず、そのディレクトリにプロジェクトが無いときも使えません。ページが扱うリポジトリで走らせます。タスクはプロジェクトの中のものなので、ページはタスクから外れ、publish が URL の後にそう言います（`page in project app, off task #9`）。付け直すなら `floe work <slug> --task <ID>`）、管理ページで決めたもの（題・お気に入り・タグ）、説明、作った日時を保ちます。`--title` と `--description` はそれより強いです。管理ページで空にしたプロジェクトは、publish したプロジェクトに戻ります。アーカイブしたページは一覧に戻ります。
- 同じ中身のもう一度の publish は、テーマを変えていてもページを描き直しますが、更新時刻と一覧の順は動きません。中身が違えば上がります。ファイルのリンクの一覧の時刻は、ファイルの更新時刻と登録した時刻の遅い方で、登録し直すと上がります。フォルダの行には時刻を出さず、一覧の並びは登録した時刻（登録し直した時刻を含む）です。

### リンクしたファイル

`--link` は、ページを保存せず、ファイルかフォルダをその場で登録します。それぞれの見せ方は [links.ja.md](links.ja.md) にあります。

- 登録できるのは、ふつうの `.html`・`.htm` のファイル、データファイル（`.yaml`・`.yml`）、フォルダだけです。データファイルは、`floe check` と同じに確かめ、誤りがあれば断ります。
- 断るもの：ホームの直下の隠しディレクトリ（設定や鍵がある所）そのものと、その中のファイルとフォルダ。`/` やホームの直下のファイルと、`/` とホームそのもののフォルダ（ディレクトリ全体を配信することになるため）。HTML のファイルやフォルダへの `--theme`。
- `--slug` の無いリンクは、同じファイルの slug（名前のものを先に）を使い、無ければ `name`・`name-2`・`name-3` … の空いた最初のものを取ります。リポジトリの中のフォルダは、プロジェクトの名前とリポジトリの中の場所（`api-docs-docs`）で名付けるので、同じ名前のフォルダが、いくつものリポジトリにあっても URL で分かれます。リポジトリの外のフォルダは、フォルダの名前（`handbook`）です。ほかのファイルへの同じ slug は、`--force` が無ければ断ります。同じファイルをどのディレクトリからリンクし直しても、ページと同じく、リンクのプロジェクトは変わりません。

## `floe check <data.yaml>...`

各データファイルを、ページを描くとおりに確かめます。YAML、テンプレートとテーマ、テンプレートの schema、checks と計算した値、描いたページです。テーマを書いていないページは、保存先の設定の既定のテーマでなく `default` で描きます。相対パスは作業ディレクトリから読みます。

- 全部のファイルの誤りを、`file:line:column: message`（ファイル全体の誤りは `file: message`）で、渡した順に出します（終了コード 1）。確かめの 1 つの段の誤りは全部まとめて出し、前の段に誤りがあれば後の段は走りません。読み方は [pages.ja.md](pages.ja.md#誤りの読み方) にあります。
- 描けたページの警告（より良い書き方の勧め）を、誤りの後に `file:line:column: warning: message` で出します。警告は終了コードを変えません。[pages.ja.md](pages.ja.md#警告) にあります。
- どのファイルも正しく、警告も無ければ何も出しません（終了コード 0）。
- 何も書かず、サーバーも起こさないので、リポジトリの CI でデータファイルにかけられます。
- データファイル（`.yaml`・`.yml`）でないファイルは断ります。
- 2 回名指したデータファイル（2 つの glob、シンボリックリンクのディレクトリ越し、macOS で大文字と小文字だけ違う名前）は 1 回だけ確かめ、最初に渡したパスで言います。

## `floe render <data.yaml>...`

各データファイルを描き、ページを `<名前>.html` としてデータファイルの隣に書きます。リポジトリが、エージェントが読み書きするデータファイルと、人が読むページを両方持てます。ページは管理ページがダウンロードするものと同じで、floe 無しで開け、見せるもの（画像、図のスタイルと拡大）を全部持ち、スクリプトが中身を外へ送らないようにする CSP を `<meta>` に持ちます。

```sh
floe render docs/spec.yaml                 # docs/spec.html を書く
floe render docs/*.yaml --out-dir site     # site/<名前>.html を書く
floe render --check docs/*.yaml            # CI で：書き直していないページがあれば失敗する
```

| フラグ | 説明 |
|---|---|
| `--out-dir <dir>` | ページを、各データファイルの隣でなく、このディレクトリに書く（無ければ作る）。 |
| `--check` | 何も書かない。無いページと、データファイルが描くものと違うページを出し（終了コード 1）、全部がそのとおりなら、描けたページの警告だけを出す（終了コード 0）。 |

- ページは変わるときだけ書き、そのパスを出します。もう一度走らせても何もしません。
- 描けたページの警告を、`floe check` と同じに stderr に出します。警告は終了コードを変えません。
- あるページは上書きします。取り戻せるように、ページはバージョン管理に置いてください。
- 誤りを `floe check` と同じに出し、全部直すまで何も書きません（終了コード 1）。2 つのデータファイルが同じページを書くとき（1 つの `--out-dir` に `a/spec.yaml` と `b/spec.yaml`、または `spec.yaml` と `spec.yml`）も何も書きません。
- 何も公開せず、サーバーも起こしません。
- ページは、描いた floe・テンプレート・アイコンによります。CI では、ページを書いたときの floe の版とテンプレートを使い、上げたらページを書き直してください。
- ページの `script` は、ファイルを開くとサーバーのページのサンドボックス無しで動きます。それでも CSP が `fetch`・XHR・ほかの所の画像・フォームを止めます。ページの間のリンク（`/a/<slug>/`）はファイルでは働かないので、ファイルどうしを相対でつないでください。

## `floe rebuild`

保存した各ページを、写したデータファイルと画像から、今のテンプレート・部品・テーマでサーバーに描き直させ、変わったページを置き換えます。自分のテンプレート・部品・テーマを変えた後や、floe を上げた後に走らせます。

- 描けなくなったページは前のままにし、誤りを言います（終了コード 1）。元のデータファイルを直してもう一度 publish するか、テンプレートを直してください。
- リンクしたファイルは開くたびに描くので、触りません。
- サーバーが動いていなければ起こします。

## `floe template list`

floe と自分のテンプレートを 1 行ずつ、タブで区切った 4 列で出します。名前、場所（`floe`、または自分のテンプレートのディレクトリ）、形（データファイルの鍵。下の part list の節）、`schema.json` の説明です。自分のテンプレートは、同じ名前の floe のものを隠します。テンプレートの書き方は [templates.ja.md](templates.ja.md) にあります。

## `floe template new <名前>`

`FLOE_TEMPLATES_DIR` にテンプレート `<名前>` を作ります。`floe template check` が通す最小の `page.html`・`schema.json`・`example.yaml` で、埋めて使います。`page.html` は viewport の `<meta>` も持ち、スマホはページを自分の幅で描きます。

- 名前は英小文字・数字・`-`・`_` で、英小文字か数字で始めます。
- 何も上書きしません。その名前のものがあれば、何も作らずに止まります（終了コード 1）。

## `floe template check`

`FLOE_TEMPLATES_DIR` のテンプレートを、自分の部品・テーマとともに `floe part check` と同じに読み、自分の各テンプレートの `example.yaml` を `floe check` と同じに描きます。

- 誤りを出します（終了コード 1）。まずファイルの誤りを出し、ファイルに誤りが無ければ見本を描きます。その後に、描けた見本の警告を出します。正しく、警告も無ければ何も出しません（終了コード 0）。
- テンプレートの中で floe が読まないファイル（`template.yaml` など）は断ります。テンプレートが持つのは `page.html`・`schema.json`・`example.yaml` と、要るなら `page.css`・`computed.yaml`・`checks.yaml`・`words.yaml`・`assets/` です。

各ファイルの中身は [templates.ja.md](templates.ja.md) にあります。

## `floe part list`

floe のテンプレートの節に書ける部品（floe の `any.json` の鍵と、そこに加わる自分の部品）を 1 行ずつ、タブで区切った 4 列で出します。名前、場所（`floe` か、自分の部品のディレクトリ）、形、説明です。`html` は HTML を字で取り、`schema.json` はありません。`floe part show html any.json` が、鍵 `html` を持つ `any.json` の全体を出します。自分の部品は `any` に加わりますが、`floe part show any any.json` が出すのは、書いてあるとおりの floe の `any.json` です。

形は、その値の書き方です。鍵を名前の順に並べ、項目の並びなら頭に `[] `、どれか 1 つだけを書く鍵なら頭に `one of ` を付けます。字なら format の名前（`markdown`・`html`）、floe の部品そのものなら部品の名前です。`-` は、一覧が言わない形です。`floe part show <名前>`（`template show`・`theme show`）の `files:` の行が読むファイルを名指し、`floe diagram example <種類>` が見本を出し、`floe diagram guide` が図の書き方を言います。テンプレートの形には、どのデータファイルにも書ける `template`・`lang`・`theme`・`title` も入ります。

`--all` を付けると、自分の schema が `$ref` で名指せる部品・見た目・共有の schema を、floe のものも自分のものも、同じ列で出します。場所は `floe` か、自分のもののディレクトリです。`floe:///parts/html.json` は無いので、`html` は入りません。

## `floe part new <名前>`

`FLOE_PARTS_DIR` に部品 `<名前>` を作ります。`floe part check` が通す最小の `schema.json`、箱の `part.html`、空の `part.css` で、埋めて使います。

- 何も上書きしません。その名前のものがあれば、何も作らずに止まります（終了コード 1）。

## `floe part check`

`FLOE_PARTS_DIR` の部品・見た目・共有の schema と `FLOE_THEMES_DIR` のテーマを floe のものの上で読み、すべての誤りを出します（終了コード 1）。共有の schema は、どれかの schema が名指すかによらず、その根から確かめます。自分の部品があれば、floe のテンプレートもそれとともにコンパイルします。正しければ何も出しません（終了コード 0）。

部品とテーマの中身は [parts.ja.md](parts.ja.md) にあります。

## `floe theme list`

テーマを、floe のものも自分のものも 1 行に 1 つずつ、`floe part list` と同じタブ区切りの 4 列で出します。名前、場所（`floe` か、自分のテーマのディレクトリ）、形（テーマは値に書かないので `-`）と、説明（`theme.yaml` の `description:`。無ければ空）です。

## `floe theme default`

管理ページの設定で選んだ既定のテーマ（テーマを書いていないページが、初めて保存されるときに持つテーマ）の名前を出します。選ばれていなければ何も出しません（そのときは `default`）。`default` を選んでいれば `default` と出します。サーバーを起こさずに、保存先（`FLOE_DIR`）の `settings.json` を読みます。ほかのコマンドが頼む保存先と同じです。

## `floe template show <名前> [ファイル]` / `floe part show <名前> [ファイル]` / `floe theme show <名前> [ファイル]`

floe のものか自分のものの、テンプレート・部品（見た目と共有の schema も）・テーマを出します。それで書く前や、写す前に読むためのものです。名前と説明、場所、読むファイルの並び（`files:`）を出します。ファイルの中身は出しません。

- ファイル名を足すと（`floe part show code part.html`）、そのファイルだけを、先頭の BOM を除いて書いたとおりに出します。floe の部品の `part.html` で、`{{copyButton}}` などの関数の使い方が分かります。読まないファイルの名前は、読むファイルの並びを言って断ります。

| 出すもの | ほかに出すもの | ファイルの順（`files:` の並び） |
|---|---|---|
| テンプレート | データファイルが選べるテーマ（`themes:`） | データファイルが書けるもの（`schema.json`・`checks.yaml`・`computed.yaml`）と `example.yaml`、後に `page.html`・`page.css`・`words.yaml`。`assets/` の画像は出さない |
| 部品 | 借りる見た目 | `schema.json`・`checks.yaml`・`part.yaml`・`part.html`・`part.css`・`words.yaml`。借りる見た目の CSS は、その見た目のもので、`floe part show panel part.css` が出す |
| 見た目 | 借りる見た目 | `part.yaml`・`part.css` |
| 共有の schema | — | `<名前>.json` |
| テーマ | — | `theme.yaml`・`palette.css`・`base.css`・`markdown.css`、その後に部品か見た目ごとの CSS を名前の順で |

## `floe list`

サーバーが並べるとおりに、ページを新しい順に出します（動いていなければ起こす）。各行はタブで区切った 4 列で、更新した日時（手元の時刻、`YYYY-MM-DD HH:MM`）、slug、題、リンクしたパス（保存したページなら空）です。アーカイブしたページは出しません。`--archived` を付けるとそれも出し、どの行にも 5 列目（`archived` か空）を足します。

## `floe rm <slug>...`

サーバーを通して、ページを順に消します（動いていなければ起こす）。最初の失敗（無いページなど）で止まります。リンクしたファイルそのものは残し、登録だけを消します。

## `floe archive <slug>...`

サーバーを通して、ページを順にアーカイブします（動いていなければ起こす）。最初の失敗（無いページなど）で止まります。アーカイブしたページは、`floe list` と管理ページの一覧に出ません（管理ページでは棚の「アーカイブ」で見られます）。URL では今までどおり開け、ダウンロードでき、`floe rebuild` で描き直されます。アーカイブ済みのページをもう一度アーカイブしても、何も変わりません。`--undo` で一覧に戻します。publish し直しても戻ります。動くのはページだけで、タスクをアーカイブへ移すのは状態です（`floe work --task X --state archived`）。

## `floe tag <slug>... --add <名前> --remove <名前>`

サーバーを通して、ページに順にタグを付け、外します（動いていなければ起こす）。最初の失敗（無いページなど）で止まります。`--add` と `--remove` は名前ごとに 1 回ずつ書き、どちらか 1 つは要ります。名前は書いたとおりに 1 つで、前後の空白だけを落とし、カンマでも分けません。もう付いている名前は 1 つのまま、付いていない名前を外しても何も起きません。`--remove` の名前を先に外し、次に `--add` の名前を付けるので、両方に書いた名前は付いたまま最後に回ります。変わるのは書いた名前だけで、その間に管理ページやほかの `floe tag` が書いたタグは残ります。

```sh
floe tag design-notes plan --add 設計 --add "cli, api"   # 2 つのページに 2 つのタグ
floe tag design-notes --remove 下書き                    # 1 つ外す
```

## `floe work [<slug>...]`

ページがどのタスクにあるかと、タスクの状態を、サーバーを通して書きます（動いていなければ起こす）。タスクはプロジェクトとタスク ID で名指し、floe はどちらの意味も読みません。どのタスクかはページが持ち（各 `meta.json` の `work`）、タスクのタイトル・状態・外のリンク・カテゴリの順と、変えた回数（`rev`。画面が送り返し、その後に書かれたタスクへの書き込みは断られます）は保存先の `tasks.json` が持ちます。ページが名指すタスクには必ず行があり、ページのカテゴリは必ずタスクのカテゴリの並びにあります（ページとタスクの 1 回の書き込みが作ります）。`tasks.json` を手で直して行の無いタスクを名指すページは、行にその名前を出し、タスクは一覧に出ません。そのページの work を書く次の書き込み（ページの `floe work`、管理ページの「タスクを設定」・ピン止め・「タスクから外す」の取り消し）が行を作ります。

ページのカテゴリは、タスクのページでタスクのページを分けて並べる所で、カテゴリごとに見出しが付きます。ユーザーが決めます。

```sh
floe work design-notes --task "#130"                             # ページをタスクに載せる
floe work --task "#130" --state doing                            # タスクの状態
floe work --task "#130" --url https://example.com/issues/482     # タスクだけ
floe work design-notes --category designs                        # タスクの中のページのカテゴリ
floe work --task "#130" --categories proposals,designs,samples   # カテゴリを見せる順
floe work design-notes --pin                                     # タスクによらずピン止め
floe work design-notes --task "#131" --parent "#130"             # #130 の子のタスクにページを付ける
floe work --task "#130" --forget                                 # タスクの行を消す
floe work design-notes                                           # ページの今を言い、何も書かない
```

書いたタスクとページを 1 行ずつ、store が残した値で言います。タスクは `made`（行が無かった）・`changed`・`unchanged`（欄を書いたが同じ値だった）と書いた欄、ページのカテゴリを足したときはカテゴリの並び、その後にページのタスク・カテゴリ・ピンです。何も変わらず欄も書いていないタスクは言いません。プロジェクトの無いタスクは `in no project` です。slug だけでフラグが無ければ、各ページを今の値で同じように言い、何も書きません。無いページの slug があれば、どのページも言う前に断ります。slug が無く `--task` だけなら、タスクを今の値（状態と、あれば題・URL・カテゴリ・親）で言い、何も書きません。行の無いタスクは断ります。

```text
$ floe work design-notes --task "#130"
task #130 in project floe: made
page design-notes: task #130 in project floe
$ floe work --task "#130" --state doing
task #130 in project floe: changed; state doing
$ floe work design-notes
page design-notes: task #130 in project floe
$ floe work --task "#130"
task #130 in project floe: state doing
$ floe work design-notes --task ""
page design-notes: no task
$ floe work --task "#130" --forget
task #130 in project floe: forgotten
```

slug を書くと、タスクのプロジェクトは各ページのものです。`--task` は各ページをそれぞれのプロジェクトのその名前に載せ、書かなければ各ページのタスクを変えます。`--project` と `--forget` はタスクだけを名指すので、slug を付けずに使います。slug と一緒の `--parent` は、1 つのプロジェクトのページとだけ使えます。slug を書かないと、`--task` がタスクを名指し、プロジェクトは `--project` です（省くとカレントディレクトリのプロジェクト、`""` は無し）。

| フラグ | 変えるもの | |
| --- | --- | --- |
| `--task <タスク ID>` | ページか、名指したタスク | slug があるとき、`""` はページをタスクから外し、カテゴリも外す。タスクを変えるもの（`--state`・`--url`・`--title`・`--categories`・`--parent`）とも、タスクが要るカテゴリとも一緒に使えない。別のタスクへ移したページは、`--category` でカテゴリを書かなければカテゴリを外す。新しいタスク ID は状態 `todo` のタスクになる |
| `--category <カテゴリ>` | ページ | slug があるときだけで、タスクに付いたページに。タスクのカテゴリの並びに無ければ、同じ書き込みで末尾に足す。`""` で外す |
| `--state <状態>` | タスク | `todo`（未着手）・`doing`（作業中）・`done`（完了）・`archived`（アーカイブ） |
| `--url <URL>` | タスク | 外のリンク 1 つ。`http` か `https`。`""` で外す |
| `--parent <タスク ID>` | タスク | slug と一緒なら `--task` も書き、ページを付ける 1 つのタスクの親になる。同じプロジェクトに行があり、親を持たないタスク。子を持つタスクには付けられない（親子は 1 段だけ）。`""` で外す |
| `--title <タイトル>` | タスク | `""` で外す |
| `--categories a,b,c` | タスク | カテゴリの順（書いたとおり）。並びに無いページのカテゴリは末尾に足し、ページのあるカテゴリを落とすと断る。ここではカテゴリの名前に `,` を書けない。`""` で外す |
| `--pin`・`--unpin` | ページ | slug があるときだけ |
| `--clear` | ページ | タスクから外し、ピン止めも外す。タスクは残す |
| `--forget` | タスク | slug が無いときだけ。ページが載っている間（アーカイブしたページも）と、子のタスクが残っている間は断る |

ページとタスクは 1 回の書き込みで書きます。先に全部を確かめ（無いページ、タスクを変えるフラグかカテゴリがあるのにタスクの無いページ、ページのあるカテゴリを落とす `--categories`）、断るときは何も書きません。その後に `tasks.json`、ページの順に書きます。その途中でシステムがページを書けなければそこで止まり、タスクとそれより前のページは書かれたまま残るので、同じコマンドをもう一度打つと揃います。ページが付くタスクに行が無ければ作り（`made`）、ページのカテゴリがタスクのカテゴリの並びに無ければ末尾に足します。`floe publish --move-project` や管理ページの「編集」でページのプロジェクトが変わると、ページはタスクから外れます。タスクはプロジェクトの中のもので、別のプロジェクトの同じ名前のタスクは別のタスクだからです。

タスク一覧は、サーバーの `/tasks` で、1 つのプロジェクトのタスクを状態で分けて並べます。プロジェクトを指さずに開くと、このブラウザで最後に見たプロジェクト（今もあるとき）、無ければ作業中で状態が一番新しく変わったタスクのプロジェクト、無ければ左の列の一番上を選び、URL に書きます。どの状態も状態が変わった新しい順で、ページの数、未読の数、リンクを出し、上にそのプロジェクトのピン止めしたページを出します。ピンの × で、ピン止めを外せます。タスクの無いプロジェクトで最後のピンを外すと、そのプロジェクトは一覧から無くなり、一覧に無いプロジェクトの画面になります。タスクの一覧の置き場所は状態だけで決まり、`archived` のタスクは、ページによらず「アーカイブ」に出ます。切り替えは、タスクが無いときも、ロゴの横に出ます。

**タスクを作成**：タスク一覧の左の列の、プロジェクトの下の「＋ タスク」（狭い画面では「絞り込み」の中）で、今のプロジェクトにタスク ID とタイトルでタスクを作ります。作ると未着手の一覧へ移り、新しい行に色が付きます。すでにある ID を打つと、そのことを言い、「タスクを開く」でそのページへ移ります。どのプロジェクトにもタスクが無い画面にも同じボタンがあり、ページのあるプロジェクトか「未設定」から選びます。ページの無いプロジェクトに作るときは `floe work --project` を使います。アーカイブの一覧と、一覧に無いプロジェクト（URL で指したもの）の画面には出ません。

タスクのページの頭の「編集」は、タスクのタイトル・URL・カテゴリを 1 つのモーダルで書きます。カテゴリは名前を変えず、並べ替える・追加する・削除するだけです。行のつまみをドラッグするか、上へ・下へのボタンで動かし（タッチの画面はボタンだけ）、一覧の一番下の「カテゴリを追加」を押して名前を打ち、Enter で追加し、行のごみ箱のボタンで削除します。削除できるのはページの無いカテゴリだけで、ページ（アーカイブしたページも含みます）のあるカテゴリのボタンは押せません。削除するには、先にページの「…」の「タスクから外す」か「タスクを設定」で、そのカテゴリから外します（アーカイブしたページの「…」にもあります）。並べた順は全部書きます。ページを付けたカテゴリはいつもタスクのカテゴリにあり（付けると足されます）、ページのあるカテゴリを並びから落とすと断られ、モーダルがそう言います。送るのは変えた所だけで、その間にほかが書いていれば断り、変えた所を残してほかを読み直します。その間に削除されたタスクは作り直しません。タスクの行を押すと、タスクのページ（`/tasks?project=…&task=…`）を開きます。ページをカテゴリごとに、`--categories` で書いた順、次に初めて付いた順で並べ、カテゴリの無いページを先に出し、どの組の中でも、アーカイブしたページはほかの後に、薄い字で「アーカイブ済み」を添えて出します。ページの無いカテゴリも見出しにし、各カテゴリの「ページを追加」で、同じプロジェクトのページ（アーカイブしたものを除く）を探してそのカテゴリに付けます。ほかのタスクやほかのカテゴリのページは、そこから移ります。上には状態を変えるプルダウン、リンク、完了になるとタスクをアーカイブするボタンがあります（`--state archived` と同じ。ページはそのまま残り、ページは行か `floe archive` で別にアーカイブします）。同じボタンでタスクを戻し、完了に戻ります。タスクのページ・モーダル・一覧からの書き込みは画面が最後に読んだ内容で送り、その間に別のセッションが書いていれば断られ、画面はタスクを読み直します。開いただけでは既読になりません。ページも子も無いタスクのページには「タスクを削除」があり、2 回押すと削除して一覧へ戻ります（`--forget` と同じ道）。ここから全面で開いたページはここへ戻り、ピン止めから開いたページはタスク一覧へ戻ります。`h` と行の上のリンクは、そのプロジェクトの一覧の、タスクの今の状態の所へ戻り、そのタスクの行にフォーカスを置きます。

全面で開いたページには、ロゴの横に戻るボタンがあり、戻る先（タスク ID、タスク一覧、ページ一覧のうち開いた元）を字で言います。`h` も同じ所へ戻ります。このボタン、`h`、ブラウザの戻るで一覧に戻ると、そのページの行にフォーカスがあり、右に同じ版のページが開きます（未読のままのページは開きません）。ロゴはいつもページ一覧へ行きます。開いた行の中に無いページ（検索や別のタブから開いたページ）は、ページ一覧へ戻ります。

ページの「…」でも同じことができます。ピン止めと外す、タスクを開く、「タスクを設定」でタスク ID、カテゴリ、タイトル（新しいタスクのとき）を書き、「タスクから外す」でページをタスクから外します（トーストの「元に戻す」で、同じタスクとカテゴリに戻ります）。タスク自身のタイトル・URL・カテゴリの順はタスクのページの「編集」で、親はそのページの親子のカードで書きます。候補にはタスクの状態が出て、タスクに入れるとトーストで言い、そのタスクのページへのリンクにします。候補に無いタスク ID は新しいタスクになり、タイトルが要ります。ページ一覧の行には、ページのタスクとピン止めのバッジが出て、押すと移れます。

**子のタスク**：親は `--parent` か、タスクのページで付けます。親も子も無いタスクのページは、頭の下に「親のタスク」と「子のタスク」の 2 段を出し、どちらも右に「＋ 追加」があります。「親のタスク」の「＋ 追加」は、そのプロジェクトの今あるタスクを親にするか、タスク ID とタイトルを書いて新しい親を作り、同じ書き込みで付けます。親のあるタスクでは、そこが「変更」になり、どこから移るかをモーダルが先に言います。親や子の行の右のボタンは、その子を親からすぐ外します（マウスでは行に重ねたときとキーで止まったとき、タッチではいつも見えます）。外したときと親を変えたときは、トーストの「元に戻す」で前の親に戻せます（前の親が親になれるときだけ）。親を持たないタスクのページの「子のタスク」の見出しの右の「＋ 追加」は、タスク ID とタイトルを書いて、ページの無い新しい子を未着手で作ります。そのプロジェクトの今あるタスクを選ぶか同じタスク ID を書くと、そのタスクが今のタイトルのまま子になります。別の親の子ならこの親へ移ると、モーダルが先に言います。子を持つタスクは断ります。親と子は別々のタスクで、一覧にはそれぞれの状態の所に出ます。子の行には親の名前、親の行には子の数が字で出ます。タスクのページは頭の下のカードに、子か親を並べ、行の頭に状態を出します。押すとそのタスクのページへ移ります（`j` `k` は止まりません）。親の状態を変えても子は変わりません。アーカイブもタスクごとで、「タスクをアーカイブ」はそのタスクだけを触り、ページ・親・子は触りません。手で書いた `parent` が決まりに合わないとき（無いタスク、自分、親を持つタスク）は、断らずに親の無いタスクとして出します。ページのプロジェクトを変えてもタスクの行は移らず、親子は元のプロジェクトに残ります。

ページの `work` は、公開し直しても、名前を変えても、描き直しても残ります。読めない `tasks.json` や、ほかの状態、`http`・`https` でない URL を持つ `tasks.json` は断り、上書きしません。手で直してください。floe の知らない行の鍵は、次の書き込みで消えます。

## `floe serve`

サーバーを `127.0.0.1` で、SIGTERM・SIGINT か `floe stop` まで前面で動かします。途中の要求を終えてから（長くて 10 秒）止まり、2 回目のシグナルではすぐ終わります。[サーバー](#サーバー) に挙げたコマンドは同じサーバーを裏で起こすので、これは主に、サーバーが起きない理由を見るためのものです（動いているサーバーに起きたことは、その `server.log` にあります）。裏のサーバーが起きなければ、`the server did not start; run "floe serve" to see the error` と言います。前面のサーバーの端末を閉じる（SIGHUP）と、2 回目のシグナルと同じくすぐ終わり、どちらも止まったことを書きません。

## `floe stop`

裏で動くサーバーを止め、止まってから戻ります（すぐ後のコマンドは、自分のサーバーを起こします）。動いていなければ `server is not running` と出し、0 で終わります。

## `floe diagram render <spec.yaml>...`

各図の spec を確かめ、図を順に、inline SVG の 1 つの HTML の断片として標準出力に出します。自分の HTML のページ（`floe publish --link` はファイルをそのまま見せるので、`<!doctype html>` と `<html lang>` を持つ文書の全体）に貼るためのものです。データファイルでは、代わりに `diagram` の部品に spec を書きます（spec の書き方は [diagrams.ja.md](diagrams.ja.md)）。相対パスは作業ディレクトリから読みます。

- spec を図の schema で確かめ、書いた言語ごとに並べて確かめます。はみ出す字、重なる部品やキャンバスからはみ出す部品、箱を通る線、交差 …（確かめることの一覧は [diagrams.ja.md](diagrams.ja.md)）。
- 全部の spec のすべての誤りを、`file:line:column: message`（spec 全体の誤りは `file: message`）で渡した順に出し、全部直すまで何も描きません（終了コード 1）。
- 文は `--lang` の言語で書きます（省けば `en`）。文にその言語が無ければ英語にします。
- 断片は、図だけに当てた `default` のパレットと、図のスタイル（パレットの CSS の変数から色を取る）と、拡大のスクリプトで始まります。図の外のページの色と変数は変わらず、図もページのものを読みません。パレットと `color-scheme: light` を図の根に置くので、ページの `:root` や、図を包む要素（暗いパネルなど）に書いた変数と color-scheme は、図に届きません。図は自分の地にパレットの `--bg`（`default` の `#f4f3f0`）を塗るので、暗いページの上では、下のように図の根に `--bg` を書かない限り、明るい箱になります。ページの色で図を描くときは、パレットの変数を図の根に、どの層（`@layer`）の外にも書きます（`.floe-zoom-tools, .floe-zoom { --accent: …; }`）。断片のパレットは層 `floe.palette` にあり、ページが先に名付けた層より後に来るので、ページの層（Tailwind の `@layer components` など）の中の規則は負け、層の外の規則は勝ちます。スタイルは図と同じ木（文書か、1 つの shadow root）に置きます。shadow root の中の図には色が付きますが、道具の並びと拡大は付きません（スクリプトは文書の中の図だけを探します）。README の勧めるブラウザで見ます。`@scope` を読まないブラウザでは、図に色が付きません。`floe part show diagram part.css` が出す CSS はパレットの変数を読むだけで自分の色を持たないので、パレットの無いページには、その CSS でなく断片のスタイルを使います。原寸より小さく描かれた図は、読む人がボタン、Ctrl / ⌘ + ホイール、ピンチで拡大し、拡大中はドラッグか矢印キーで動かします。ページに 1 回あれば足り、2 回以上あっても害はありません。

| フラグ | 説明 |
|---|---|
| `--lang <タグ>` | 図の文を書く言語（`en`・`ja`）。既定は `en`。 |
| `--no-assets` | スタイルと拡大のスクリプトを除いて図を出す。それを持つページ向け。 |

## `floe diagram inspect <spec.yaml|data.yaml>...`

各図を `floe diagram render` と同じに確かめ、各部品の置かれた所を出します。線が狙った行に着いているか、ラベルが狙った範囲に入っているかを、絵を見ずに確かめられます。

```text
page.yaml:8:9: diagram "The API" 560x190
frame "cloud" 20,20 300x150
the heading of frame "cloud" 60,26 74.88x18
the icon of frame "cloud" 20,20 31x31
edge [60,10]→[60,120] M60,10 V120
```

- 根に鍵 `template` があるファイルはデータファイルで、テンプレートの schema で確かめた後の図を、`details`・`tabs`・`columns`・`entries`・`checks`・`options` の項目の `parts` の中も含めて、書いた順に読みます。ほかのファイルは spec です。図の外でも schema が断る誤りがあればファイルごと止まります（その下にあるものについて何も言えないため）。
- 図ごとに、書いた場所（`file:line:column:`。spec は `file:`）、題、キャンバスの大きさの行を出します。その下に 1 行ずつ、部品の範囲、枠の見出し、線の道と両端、ラベルの範囲と、それが入る円を出します。
- 置かれた所は標準出力に、誤りは標準エラーに出し、誤りがあれば終了コードは 1 です。検査で断る図も、参考として出します。直すと部品や線が動くことがあり、誤りのある `graph` は、できた分だけか、丸ごとありません。配置まで届かない図（YAML や schema の誤り、無い `example`）は、1 行も出しません。
- データファイルのテンプレートと部品の checks は走らせず、ページのほかの所（format `html` の項目、画像、部品の関数が断るもの）も確かめません。ページ全体を確かめるのは `floe check` です。自分の部品が `{{diagram}}` で描く図は出ません。`template` を忘れたデータファイルは spec として読み、spec の言葉で断ります。`template` を書いた spec はページとして読みます。

## `floe diagram example [種類]`

種類を書かなければ、組み込みの見本を、図の種類ごとに 1 つ（構成図、AWS の構成図、floe が配置する AWS の構成図、クラス図、ER 図、フロー図、ガントチャート、Git のブランチ、組織図、4 象限、シーケンス図、状態遷移図、スイムレーン、年表、ベン図）並べます。各行は、`floe part list` と同じく、タブで区切った種類・場所（`floe`）・形（見本は写すもので値に書かないので `-`）・要約です。種類を書けば、その spec を出します。コメントが、配置に使った格子を説明します。どの見本も確かめを通ります。文は英語と日本語の両方を持ち（`{en: …, ja: …}`）、spec と同じ書き方です。AWS の見本は 2 つとも AWS のアイコンを描くので、`floe icons fetch aws` の後に描いてください。

## サーバー

- `floe publish`・`floe rebuild`・`floe list`・`floe rm`・`floe archive`・`floe tag`・`floe work` は、サーバーが動いていなければ起こし、動いていればそれを使います。
- これらはサーバーに、ページを確かめ・保存し・描き・並べ・消すよう頼みます。保存先に書くのはサーバーだけです。publish はデータファイル（とサーバーが求める画像）を送り、サーバーが自分のテンプレート・部品・テーマ・アイコンで確かめて描きます。
- floe を入れ直す（別の版、またはビルドし直したバイナリ）と、次のコマンドが動いているサーバーを止めて自分のものを起こし、標準エラーに `stopping the server on port 7325 (pid 1234), which was of another build of floe, to start this build's` と言います。そのあと新しいサーバーが起きなかったとき、サーバーが止まらなかったときも言います。いくつかが一緒に頼んだときは、サーバーが頼みを受けた 1 つが言います。
- サーバーは `floe stop`、別のビルドのコマンドによる入れ替え、ログアウト、再起動まで動き続けます。
- サーバーは自分に起きたことを、保存先（`FLOE_DIR`）の `server.log` に書きます。起きたこと、止まることとその理由（`floe stop` か別のビルドのコマンド、SIGTERM か SIGINT）、止まったこと、panic した要求（スタック付き）、落ちたときに runtime が書いたもの（この行には時刻も pid も付きません）です。行は `time=` と `pid=` のあとに `key=value` が並ぶ形で、スタックは 1 つの `stack=` の値に、改行を `\n` と書いて入ります。panic した要求には、スタックの場所を言う 500 で答え、サーバーは動き続けます。`server.log` が 1 MiB を超えていれば、次の起動で `server.log.1` に移し、前の `.1` は置き換わります。SIGKILL・SIGHUP・2 回目のシグナル・電源断で終わったサーバーは終わりを書かず、最後の行が、動いていると言う行になります。止まっている途中（長くて 10 秒）のサーバーがあるうちに次のサーバーが起きて server.log を回すと、その最後の行は `server.log.1` に書かれます。`server.log` がふつうのファイル（FIFO・ディレクトリなど）でないと、`floe serve` は始まりません。
- サーバーは、起こしたコマンドの `FLOE_TEMPLATES_DIR`・`FLOE_PARTS_DIR`・`FLOE_THEMES_DIR`・`FLOE_ICONS_DIR` で描きます。1 つのコマンドにでなく、どのコマンドも受け取るシェルの環境に設定してください。
- 違うものを使う `floe publish` と `floe rebuild` は、`floe stop` まで断ります。`floe list`・`floe rm`・`floe archive`・`floe tag`・`floe work` は描かないので、どれでも通ります。ただし、floe を入れ直した後にサーバーを置き換えるものは、新しいサーバーがそのコマンドのもので描くので、違うものでは断ります。
- 1 つのサーバーは、そのポートで 1 つの保存先（`FLOE_DIR`）を配信します。動いている間、ほかの保存先へのコマンドは断り、サーバーが配信している保存先を伝えます。コマンドをそのサーバーに送るなら、`FLOE_DIR` をその保存先にしてください。そのあとは上の行のとおりです（`FLOE_TEMPLATES_DIR` などが違えば断り、別のビルドのサーバーは入れ替わります）。自分の保存先を使うなら、その保存先に別の `FLOE_PORT` を使うか（シェルの環境に置くと、どのコマンドにも渡ります）、`floe stop` を実行してからコマンドをもう一度実行してください。
- `127.0.0.1` だけで待ちます。ほかのホスト名（DNS リバインディング対策）と、ほかのサイトからの書き込みは断ります。
- 保存したページは描いたとおりに返し、CSP とサンドボックスを付けます。ページはサンドボックスで動くので、スクリプトは管理ページの API に届きません。枠がページから受けるのは、読んだことと、移ることやモーダルを開くキーだけです。
- publish でデータファイルか画像が変わると、保存したページの新しい版ができます。同じ中身の publish、`floe rebuild`、管理ページでの変更では、版はできません。版は新しいものから 20 まで残り、古いものから消えます。
- 保存先の `reads.json` に、保存したページをどの版まで読んだかを持ちます（リンクとフォルダは持ちません）。floe が初めて書く前からあるページは、読んだものとして扱います。`floe serve` が読めないときは `reads.json.broken` に移して新しく作り、どのページも読んだ扱いになります。中身を残すには手で直します。開いたページが既読になったときのトーストと、ページの「…」のメニューの「未読に戻す」で、開く前の見た目に戻せます。もう一度開くと既読になります。アーカイブしたページは未読になりません。行に点・太字・新しい版の札を出さず、未読の数にも入らず、トーストにも「…」にも「未読に戻す」を出しません。
- データファイルから描いたページのスクリプトは、ページの中身を `fetch`・XHR・ほかの所の画像・フォームで外へ送れません（ダウンロードしたものも）。リンクした HTML は、読むものを読みます。
- ページは URL が名指す所（`/a/<slug>/#part`）で開き、ページの中で動いた先を URL に残すので、URL の写しや読み直しでその所が開きます。
- 管理ページは、ページを 1 つのファイルでダウンロードします。保存したページかリンクしたファイルで、CSP を `<meta>` に入れます。
- 管理ページの設定（一覧の上の帯の右端の歯車。幅が 40rem より広い窓で出ます。ページを全画面で開いたときは出ません）で、既定のテーマを選びます。floe のテーマと自分のテーマを、それぞれのテーマで描いた見本のページのカードから選びます。テーマを書いていないページは、初めて保存するときにそれを持ちます。保存済みのページは変わりません。保存先は `settings.json` に持ちます。`settings.json` を読めないと、データファイルから描く新しいページを断ります。テーマを選び直すと、丸ごと書き直して直ります。
- ページの「…」の「テーマ」で、データファイルから描くページ（保存したページとリンク）のテーマを選びます。選んだテーマはそのページだけを描き直し、`--theme` と `theme:` より強く、publish し直しても rebuild しても続き、ほかのファイルのページに置き換える（`--force`）と消えます。最初のカード「このページのテーマを外す」は、外したときに表示するテーマ（`--theme`・`theme:`・初めて保存したときの既定のテーマ）を示し、選ぶとそのテーマに戻ります。そのテーマで描けなければ、ページは前のままです。
- 版が 2 つ以上ある保存したページは、どの 2 つの版の間でも、後の版のページそのもの（テーマも部品もそのまま）の上で違いを見られます。足した字は緑の下線、消えた字は元の場所に赤の打ち消し線で出ます。一覧・節・部品の中で消えたものは、前の版の形のまま、部品の後ろ（残ったものより前にあったものは部品の前）に打ち消し線で出ます。表の消えた行とセルは表の中の元の位置に、番号付きの一覧の項目は元の番号で出ます。変わった図と画像には枠が付き、その下で前の版を開けます。枠は、字の印で違いを見せられない所にだけ付きます。目次には変わった節が並び、`n` `p` で次・前の変わった所へ移ります。ページの上の「差分」から開き、新しい版を初めて開いたときは、前に読んだ版から何節変わったかを知らせます。差分を開いても既読になりません。閉じるとページを開くので既読になります。リンクとフォルダには版がありません。太字やリンクの先、CSS の違いは出ません。字の中の画像は alt で比べます。
- 枠の中のページを印刷すると 1 画面分しか紙に出ず、ページだけを開いて印刷するよう知らせが出ます。
- 管理ページはキーで操作でき、`?` でヘルプが開き、その画面で使えるキーの一覧が出ます。ヘルプのもう 1 つの「ページ一覧について」か「タスク一覧について」は、その画面が何か、画面の言葉が何かを説明します（ページ一覧とページ全面ではページ一覧、タスク一覧とタスクのページではタスク一覧）。一覧の帯の、設定の前の ? のボタンは、そこを開きます（幅が 40rem を超える窓。ページ全面には無い）。`Ctrl+K`（`⌘K`）でページを検索します。一覧では、`j` `k` か `↑` `↓` で行を移り、`Enter` で全画面に開き、`x`（か行のメニューの「選択」）で選択、`f` でお気に入り、`/` で検索欄へ移ります。右に開いている行をもう一度押しても（ダブルクリックでも）全画面に開きます。開いているページは `d` で差分を開きます。全画面では、`j` `k` で開いた行の次・前へ移り、`h` で戻るボタンの行き先へ戻り、`f` でお気に入り、`d` で前に読んだ版からの差分（`n` `p` で次・前の変わった所へ移り、`d` で閉じます）、`/` でページを検索します。ページの中を押した後も、floe が描いたページでは `j` `k` `h` `d` `?` `/` `Ctrl+K` が、リンクした HTML ではページが字のキーを使うことがあるので `Ctrl+K` だけが働きます。

## 環境変数

| 変数 | 説明 |
|---|---|
| `FLOE_DIR` | ページの保存先。既定は `$XDG_DATA_HOME/floe`、無ければ `~/.local/share/floe`。 |
| `FLOE_PORT` | ポート（既定は `7325`）。1〜65535 の 10 進の数。 |
| `FLOE_ICONS_DIR` | `floe icons fetch` がアイコンのセットを 1 つずつディレクトリ（`aws`）で置く所。既定は `$XDG_DATA_HOME/floe-icons`、無ければ `~/.local/share/floe-icons`。 |
| `FLOE_TEMPLATES_DIR` | 自分のテンプレートを 1 つずつディレクトリで置く所（[templates.ja.md](templates.ja.md)）。既定は `$XDG_CONFIG_HOME/floe/templates`、無ければ `~/.config/floe/templates`。 |
| `FLOE_PARTS_DIR` | 自分の部品・見た目・共有の schema の置き場所（[parts.ja.md](parts.ja.md)）。既定は `$XDG_CONFIG_HOME/floe/parts`、無ければ `~/.config/floe/parts`。 |
| `FLOE_THEMES_DIR` | 自分のテーマを 1 つずつディレクトリで置く所（[parts.ja.md](parts.ja.md)）。既定は `$XDG_CONFIG_HOME/floe/themes`、無ければ `~/.config/floe/themes`。 |
| `BROWSER` | 新しいページを開くコマンド。既定は macOS では `open`、ほかは `wslview` か `xdg-open`。 |

`FLOE_*` のディレクトリは絶対パスにします。floe はどこで動かしても 1 つの所を読むので、相対パスは断り、どのシェルも読まなかった `~` で始まるものも断ります（`FLOE_PARTS_DIR is ~/x, a relative path; set it to an absolute path`）。相対の `XDG_DATA_HOME`・`XDG_CONFIG_HOME` は、XDG の決まりどおり無いものとします。

コマンドは、自分が使う設定だけを、使うときに確かめます。設定したディレクトリが使えないとき（ディレクトリでない、読めない・書けない、自分のテンプレート・部品・テーマなら無い）は、変数の名前で断ります。

```text
floe: FLOE_PARTS_DIR is /tmp/t/missing, which cannot be used as a directory (no such file or directory); make it a directory floe can use, or set FLOE_PARTS_DIR to another directory
```

- `FLOE_TEMPLATES_DIR`・`FLOE_PARTS_DIR`・`FLOE_THEMES_DIR` は、ページを描くか自分のものを読むコマンド（`floe check`・`floe render`・`template` と `part` のコマンド、描くサーバー）が使うので、設定したものが無ければそれらを止めます。既定の場所が無ければ、自分のものは無いとし、floe のものだけで描きます。既定の場所があってもディレクトリでなければ断ります。
- `FLOE_DIR` はサーバーと、それを使う [サーバー](#サーバー) に挙げたコマンドが使い、無ければ作ります。`FLOE_ICONS_DIR` は icons のコマンド（無ければ作る）と、アイコンを置いた図（その図の所で）が使います。
- `HOME` が無い（または絶対パスでない）とき、ほかに既定の無いディレクトリは無いものとします。`floe check` は floe のテンプレート・部品・テーマだけで走り、そこに書くコマンド（`floe template new`、`FLOE_DIR` を使う `floe list` …）は変数を設定するよう求めます。
- `FLOE_PARTS_DIR`・`FLOE_THEMES_DIR`・`FLOE_TEMPLATES_DIR` は重ねません。2 つが同じディレクトリか、一方がもう一方の中にあれば（symlink を通しても）、中を読む前に、2 つの変数の名前で断ります。設定したものは、まだ無くても比べます。コマンドは自分が読むものだけを比べ、既定の場所は有るときだけ比べます。`floe part new`・`floe template new` は、作るものがほかの種類の置き場所の中に入るか、それを含むなら、作らずに断ります。

```text
floe: FLOE_PARTS_DIR (/tmp/pp) and FLOE_THEMES_DIR (/tmp/pp) are one directory, or one is in the other, where floe would read the files of one as those of the other; make FLOE_PARTS_DIR and FLOE_THEMES_DIR two directories, neither in the other
```

## 終了コード

| コード | 意味 |
|---|---|
| `0` | 成功 |
| `1` | 失敗と、floe が断る値（断った publish、無いページ、使用中のポート、誤りのあるデータファイルや図の spec、無い見本 …） |
| `2` | floe が読めない、または要るものが足りないコマンドライン（知らないフラグやコマンド、足りない引数） |
