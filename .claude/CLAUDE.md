# CLAUDE.md

floe はエージェントが書いた HTML ページをローカルサーバー（`http://127.0.0.1:7325`）で表示・管理する Go の単一バイナリです。dotfiles（[azarashi](https://github.com/sukekyo26/azarashi)）の `profiles/bedrock/.agents/skills/artifact` にある JS 実装を移植し、データ（YAML）とテンプレートから文書を組み立てる機能と、検査付きの inline SVG 図を足します。

- 検証は `just ci`（CI と同じ内容）。golangci-lint は `just setup` で入る。
- 対応 OS は linux と darwin（amd64・arm64）。Windows はリンクのパス検査などの信頼境界を検証できないので対応しない。

## floe でページを作って困ったことは、ユーザーに伝える

floe はエージェントが使う道具なので、エージェントが使っていて困ったことがそのまま直すべき点になる。データファイル・テンプレート・部品・テーマでページを作っていて、次のようなことに気付いたら、ユーザーに伝える。

- 誤りの文が、何をどう直せばよいかを言わない（推測で直した）。行と列が原因を指していない
- 検査を通ったのに、ページが崩れて描かれる（検査の漏れ）。逆に、正しいデータを断る
- 同じものを何度も書き写す、回り道をしないと書けないなど、書きづらい

伝え方:

- 気付いた時点で、作業の報告の中で伝える。作業の終わりまでためない。
- 回避して作業を続けたときも、回避したことと、その方法を伝える。黙って回避しない。
- データファイルの断片と floe の出力をそのまま添え、どこで困ったか、直し方の案があればそれも書く。
- floe 本体を直すかはユーザーが決める。頼まれた作業の中で、断りなく直さない。

ページにも書く:

- 伝えた問題は、floe のページ「floe を使っていて困ったこと」（slug は `floe-usage-issues`、データファイルは `~/.local/share/floe-plans/floe-usage-issues.yaml`）に追記し、`floe publish` で公開し直す。問題ごとにページを増やさない。
- 先頭のまとめの表（問題・困ること・急ぎ・直す大きさ）に 1 行足し、問題の節を 1 つ足して「何が起きるか」（データの断片と floe の出力）、「なぜ困るか」、「どう直すか」を書く。
- すでに載っている問題なら、その節に新しい例を足す。直ったら、まとめの表の急ぎを「直した」にし、直した PR を書く。
